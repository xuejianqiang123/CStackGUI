## 0. 学习结论：py880 是什么

一套「拖拽画窗体 → 生成 Python UI 代码 → 打包 EXE → 做安装包」的全中文桌面开发工作台。
宣传语「说出需求，AI 搭界面。哪里不满意，直接拖着改。」

它自报的十项能力（官网 + 知乎/百家号稿）：

| # | py880 能力 | 它的做法 |
|---|---|---|
| F1 | **AI 协作改界面** | 选中当前控件 → 让 AI 直接改（"把当前选中的按钮改成成功色"）→ 人工与 AI 的修改**统一 Ctrl+Z 撤销** |
| F2 | **窗体引用**（标"原创"） | 子窗体独立设计，主窗体引用已有窗体，**设计阶段就能看到整体布局**；业务功能一个子窗体一块 |
| F3 | **网格自由拖动**（标"原创"） | 拖控件调整位置**或交换**；拖表头交换整行整列；拖边缘调整跨行跨列；小网格提示占用范围；行列尺寸批量设置 |
| F4 | **TableLayoutPanel 弹性布局** | 自适应行高列宽、百分比布局、**混合弹性**（部分行列固定、部分伸缩） |
| F5 | **AI 数据大屏生成** | 业务需求 → 结构化提示词 → AI 生成 → Python 接真实数据（Excel/CSV/库/接口）→ HTML+JS → 嵌进桌面应用 |
| F6 | **主题与增强控件** | 整套配色可视化修改、**多窗体统一使用**、复制主题做自己的配色；日期组件等增强控件（高 DPI、双语） |
| F7 | **工作台五步** | 新建项目 → 准备环境 → 预览与运行 → 打包 EXE → 制作安装包，内置 Python 与环境 |
| F8 | **生成 UI 代码时保留已有业务代码** | 重新生成界面不会冲掉业务逻辑 |
| F9 | 全中文界面 + 内置依赖 + 30 分钟示例入门 | 「跟着案例开始」 |

## 2. 本轮 spec

### 要什么

画布从**单选**升级为**多选**，并给出配套的**对齐/分布**动作。

1. **多选**：Shift/Ctrl + 点击（画布与层级面板都能用）；空白区拖拽**框选**；Ctrl+A 全选；Esc 取消。
2. **多选联动**：整组拖动（保持相对间距）；Delete 批量删除；方向键批量微移；Ctrl+D 批量复制。
3. **对齐/分布工具条**：选中 ≥2 时，画布顶部浮出一条，含
   - 水平：左对齐 / 水平居中 / 右对齐
   - 垂直：上对齐 / 垂直居中 / 下对齐
   - 分布：横向等距 / 纵向等距（需 ≥3）
   - 尺寸：等宽 / 等高 / 同尺寸（取选中项里的**最大值**）
4. 对齐/分布/拖动都走**一次撤销**（一次操作 = 一步历史）。

### 为什么

- 补一条**自己文档里写明的缺口**；
- 它是"组 / 批量属性 / 多窗体布局"的地基；
- 纯画布侧，`.cgui` 一个字都不改 → 运行时零影响、零回归面。

### 验收标准（每条都要能失败）

| # | 验收 | 怎么验（会红的方式） |
|---|---|---|
| A1 | Shift/Ctrl 点击能加选/减选；主选框（最后点的）是实线、其余虚线 | 截图看框线；只点一次时只有一个实线框 |
| A2 | 空白处拖框选能选中区域内控件 | 框住 2 个 → 提示条显示"2 个控件" |
| A3 | 整组拖动后**相对间距不变**；且容器与其子控件同时被选中时**不会双倍位移** | 造一个 `group` + 它里面的 `button`，两者都选中，拖 10px：button 相对 group 位移必须是 0（双倍位移会变 20） |
| A4 | 对齐 6 种都对到**选中项的外接框**；等距把首尾固定、中间均匀 | 三个不同宽的控件做"横向等距"，量间隙相等 |
| A5 | 一次操作 = 一步撤销 | 连做 3 次对齐 → Ctrl+Z 三次回到初始三态 |
| A6 | 多选只改坐标，`.cgui` 结构与字段**完全不变** | `tools\check-format.bat` 过（含 .cgui 往返探针） |
| A7 | 单个控件的老行为一字不变（点选、拖动、8 向缩放、拖进/拖出容器） | 单选用例手测 + 截图 |

### 非目标（本轮明确不做）

- 不做"组/组合"（把多选持久化成文档里的一个组）—— 那是 `.cgui` 契约变更。
- 不做批量属性编辑（多选后改字体/颜色）—— 下一轮。
- 不做 py880 的"拖控件交换位置"—— 见 §1 的 kill。
- 不做多窗体/窗体引用、主题编辑器、代码生成分区保留、.cgui 热重载 —— 见 §1 的 defer。

### 能改什么 / 不能改什么

**能改**：`designer/src/**`（画布侧）、`designer/src/styles.css`、本计划文件、`README.md` §1.3 那一条已知边界（做完要销账）。

**不能改**：
- `runtime/**` —— 一个字节都不动（本轮不涉及运行时可识别的任何东西）。
- `designer/src/model/parse.ts` / `serialize.ts` 的字段读写行为 —— `.cgui` 结构不变。
- 既有单选语义的**外部表现**：`Inspector` 仍显示"主选框"那个控件的属性。

### 关键设计决定（定了，理由在这）

- **对齐基准 = 选中项的外接框**（业界通例，不用"主选框"当基准，省得解释哪个是主）。
- **等宽/等高/同尺寸取最大值**，不取"第一个选中"：把小的放大比把大的缩小安全（不会切掉文字）。工具条 tooltip 里写明。
- **容器与其子控件同时选中时，剔掉子控件**（`topLevelOnly`）：否则容器动一次、子控件再动一次 = 双倍位移（坐标是相对的）。拖动、对齐、分布三处共用这一个归一化。
- **多选拖动时不做"重新判定归属容器"**：单选的归属判定逻辑（`Canvas.tsx:169-203`）保持不变，多选时跳过。理由：多选跨容器拖拽的归属语义没有公认答案，宁可不做也不要做出一个意外结果。
- **框选只在客户区空白处生效**（`group/card` 的框体是控件本身，点击仍是选中它）—— 保持既有命中语义，不引入"点容器内部选中容器还是框选"的二义。

## 4. 边界与异常清单

| 场景 | 预期行为 |
|---|---|
| 选中 2 个 → 其中一个被 Delete / 撤销弄没了 | doc 变化后自动从选择集里剔除失效 id，不崩 |
| 多选中含 `menu`（无矩形、`rect` 为 0） | 参与对齐会把它挪到 0 附近；**接受**（它本来就在窗口框架上，`absRect` 给的就是 x/y） |
| 多选框里有 `tabs` 的子控件（`page` 不同） | 照常按坐标对齐，不动 `page` |
| 只有 1 个选中 | 工具条**不出现**（避免占地方）；分布按钮在 2 个时也禁用（需 ≥3） |
| 拖动位移 < 3px | 不进历史、不改坐标（沿用既有阈值），**框选同理** |
| 框选 0 个 | 视为"点空白"→ 清空选择（非 Shift 时） |
| Ctrl+A 全选后对齐 | `topLevelOnly` 剔掉子控件 → 实际只对齐顶层；这是**正确**行为，不是 bug |
| 缩放 ≠ 100% 时框选 | 框选坐标要除以 zoom（和拖动同一套换算） |
| 撤销栈 | 一次对齐/一次整组拖动/一次框选后删除 = 各一步 |

### 遗留（本轮明确不做 / 已知边界）

- 🟡 **多选拖动不做容器归属重判**：把一整组从分组框里拖出来，它们仍留在那个容器内（相对坐标可能为负）。想搬容器就先单选拖一次。
- 🟡 **框选只在客户区空白处起手**：在分组框内部按下 = 选中该容器（改动前就有的语义），框不到框里的控件；那些控件用层级面板 Shift 点选。
- 🟡 **多选不整组缩放**：8 个手柄只服务主选框。
- 🟢 观测：`menu` / `timer` 这类无矩形控件也会被对齐写 rect —— 运行时不读它们，只让文件里多几个数字。
- 🟢 观测（**改动前就有，非本轮引入**）：从控件箱拖入控件时用 `.stage` 的矩形换算落点，比实际指针低一个标题栏 + 菜单栏的高度。本轮不动它，免得和选择集改动混在一起审。
