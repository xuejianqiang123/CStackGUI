# 系统性重构方案：行业规范对齐（2026-10-17）

## 0. 第一性原理结论（先说结论）

**这个工程的"骨架"已经符合行业通行规范，真正的债务是点状的。** 重构前盘点（全仓 grep + 逐层走查）证实：

- `runtime/` 已按 core / kit / skin / win32 四层分目录，且分层不是"口头约定"而是**机器契约**（`tools/check-layers.mjs` 锁死 include 方向、基名唯一、业务层不碰 Windows 头、工作线程只在串口/网口文件）；
- 命名主体统一：公共 API `cg_*` snake_case、类型 `_t`、宏/枚举 `CG_`、win32 内部 `cgw_`、Win32 回调 `XxxProc`（规范见 `.codebuddy/skills/firmware_code_style/SKILL.md`）；
- 注释有 Doxygen 机器门禁（`tools/check-comments.mjs`，单测前置）；
- 构建/测试/门禁链完整：`build-all.bat`（编译全部示例 + 逐个 `--selftest`）、`tools/run-tests.bat --full`（单测 + 分层 + 注释 + 契约 + modeljs 往返）。

因此**不做推倒重来式的大搬家**。目录大迁移会同时炸掉以下硬编码路径契约（任何一处漏改都是"构建成功但运行炸"级事故）：
`designer/package.json` extraResources（`../runtime/include/cstackgui.h` 等 6 处）、
`designer/electron/cgbuild.mjs`（runtime 源码按层目录扫描 + 产物路径）、
`tools/run-tests.bat:59`（`-Iruntime\include -Iruntime\src\core …`）、
`tools/check-format.bat`（5 条示例 exe/cgui 路径）、
`tools/check-layers.mjs`（四层目录结构即契约本身）、
`.clangd` / `tools/gen-cc.mjs`（compile_commands.json 路径基准）。
风险极高、可维护性收益为零 —— 结论：**结构保持，债务点状清除**。

## 1. 目录结构：现状即目标（职责与对应关系）

```
CStackGUI/
├─ runtime/            C 运行时库（唯一随产品分发的二进制来源）
│  ├─ include/cstackgui.h   公共 API 单头（业务代码唯一 include）
│  ├─ src/core/             平台中立框架层：文档模型/控件/事件/布局/时钟（可移植，禁 windows.h）
│  ├─ src/win32/            Win32 后端：窗口过程/绘制/同步（只经 cg_win_internal.h 对内）
│  ├─ src/skin/             外观内核：自绘边框/圆角/配色（低于 win32，可整层替换）
│  ├─ src/kit/              无 UI 支持库：串口/网络/文件/编码/校验/无线（业务可见能力）
│  └─ res/                  图标/manifest/rc 资源
├─ designer/           Electron 画布（electron/ 主进程+构建器、src/ React 前端、model/ 数据模型）
├─ examples/           30 个示例工程（含 base/ 六课教学线）——同时是回归资产（--selftest）

├─ tools/              机器门禁与辅助脚本（check-*.mjs/.bat、run-tests.bat、截图 ps1）
├─ docs/               ARCHITECTURE.md / CGUI-FORMAT.md / COMM.md / M3-SKIN.md（与代码互为镜像，有门禁）
├─ common/             roundtrip 门禁运行时夹具（port_dlg.cgui，git 未跟踪，禁清理）
├─ packaging/          发布模板与校验（build-app.bat 模板、check-format、splash）
├─ apps/               用户自有工程落点（不参与 build-all）
```

旧结构 = 新结构（identity mapping）。逐目录职责见上注。**明确不迁的三处及理由**：
1. 根目录 5 个 `build-*.bat`：用户/文档入口，行业惯例（Makefile 也在根）。
2. `common/`：roundtrip 门禁夹具所在地，清理即门禁静默变红（历史事故）。
3. 示例的 `.o/.exe/.a` 产物留在示例目录：`cgbuild.mjs` 输出路径与"exe 旁放 .cgui 即可运行"的分发形态耦合，迁移会改变运行行为；已识别，不改。

## 3. 明确不做（附判据）

- **-1 字面量（约 210 处）不替换**：`-1` 是文档化的统一失败约定，本身不是"不一致"；全替换是纯 churn。
- **hex 辅助函数不跨文件合并**：`hexval`(wireless) 与 `kit_hex_val`(str) 语义相同但只有 8 行；合并要求 `cg_kit_wireless.c` 引入 `cg_kit_internal.h`（连带 UNICODE 宏与 core 内部头，该文件有"typedef 参数错位写坏栈"的历史事故、编译环境被刻意控制）。**为 8 行去动一个被事故史保护的文件，是负收益。** `hex4`(core/json, 4 字符批量解析) 与 `digest_hex`(摘要→堆串) 语义本就不同，不算重复。
- **不引入 CMake/clang-tidy/新框架**：现行 .bat+node 已覆盖全部门禁需求，违反"不引入重型基础设施"。
- **examples 侧 `n == -2` 不改**：示例是教学材料，本地 `PREP_TOOLONG` 等语义名比库枚举更贴业务；数值契约不变。
