# 窗口 / 控件截图（`cg_win_screenshot` / `cg_widget_screenshot`）

目标：现场出问题时一键取证 —— 把整个窗口或某个控件存成 PNG，路径贴进工单。
零新增链接依赖（GDI+ 早就在链接表里，也早在建窗口时 `GdiplusStartup` 过）。

## 三个刻意的选择（写在 cg_win_shot.c 文件头）

1. **PrintWindow 优先，抓屏兜底。** PrintWindow 让窗口自己画到内存 DC ⇒ 窗口**被挡住、
   不在前台**也拿得到正确内容（抓屏拿到的会是遮挡物）。少数控件不响应 ⇒ 退回 `BitBlt`，
   并**在日志里说明"这张是抓屏来的、可能被遮挡"**：宁可让人知道，也不给一张空图当证据。
2. **PNG 编码器 CLSID 写死，不枚举。** 常规做法是 `GetImageEncoders` 挑 `image/png`，
   但本项目对 GDI+ 是**按 ABI 手写声明**的（MinGW 的 gdiplusflat.h 在 C 下编不过），
   而 `ImageCodecInfo` 是 13 字段结构体 —— 手写布局错一位就是内存踩踏。PNG 的 CLSID 是固定值
   （`{557CF406-1A04-11D3-9A73-0000F81EF32E}`，按 GUID 内存布局写），
   写死它就不必碰那个结构体：**少一份手写 ABI，少一份踩踏风险**。
3. **GDI+ 起不来就返回 0。** 那种机器上 `image` 控件本来也只画占位框，如实报失败比给空图好。

## 验证（分层，各管一段）

| 层 | 手段 | 结果 |
| --- | --- | --- |
| 接口契约 | `tests/unit/test_shot.c`：NULL app / NULL 路径 / 空串 / 没有窗口 / 控件没有原生窗口 | 一律返回 0 不崩，不留半个文件 |
| 真机出图 | `build\shotprobe\`：探针在 `on_ready` 里各存一张，**图逐张看过** | 整窗图带标题栏与全部控件；控件图正好是目标输入框；另有外部抓屏做对照，内容一致 |
| 像素/观感 | 人眼看图（无法断言） | ✓ |

## 顺带修掉的两处（都在本片内发现）

1. `designer/src/model/parse.ts` 里 `intOf` / `boolOf` 在上一片改成 `intOk` / `boolOk` 后
   成了**死代码**（tsc 的 `noUnusedLocals` 会报 TS6133）⇒ 删掉，并把头部注释的"四套对齐版"
   改成实际存在的四个函数名。
2. **我自己的一次假验证**：用 `cmd` 的 `&` 并行跑命令时 `%errorlevel%` 读到的是启动前的旧值，
   于是"TSC_EXIT=0"是假的。以后一律把门禁输出写文件再读文件（见记忆里的那条教训）。

## 已知缺口

- 本片**没有进示例**：gallery 的布局已排满（工具条那一行放不下），为它挪控件有视觉回归风险，
  不值当。使用方式写在头文件与 `CGUI-FORMAT` 第 6 节，画布「支持库」里也能查到。
- 多窗口拼的控件（日期时间）只存主窗口那个 —— 已在注释与文档里写明。
- 不抓光标、不抓鼠标位置（取证场景不需要；将来要标红框再说）。
