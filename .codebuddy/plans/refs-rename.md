## 1. 要解决的问题（缺陷陈述）

`.cgui` 里有两张「按名字引用」的表：顶层 `styles{}`（命名样式）与 `actions{}`（命名动作）。
引用的地方：

- **样式**：每个控件的 `style`，三种形态 —— `"style": "log"` / `{"use":"log",...覆盖}` / 内联对象（不引用）
- **动作**：每个控件的 `action`，以及每个树节点/菜单项的 `action`（`CgTreeItem.action`）

**缺陷**：两个对话框的改名只搬了表里的键，**一个引用都不更新**。
- `designer/src/components/StyleDialog.tsx:184-192` `renameStyle`
- `designer/src/components/ActionsDialog.tsx:172-180` `renameAction`

后果具体：把 `log` 改名成 `logStyle` 之后，引用它的几十个控件全部变成「引用不存在的样式」——
运行时按"没有命名样式"静默处理（外观悄悄变了），`--selftest` 报「样式引用失效」。
**而本工程已经有正确的先例**：`Inspector` 改控件 id 时会连带改 `bind.src`（见 `designer-modify` 技能）。
所以这不是有意设计，是半个实现——只不过被 5 处文案写成了"约定"，见 §4。

## 2. 本轮 spec

1. **改名连带更新引用**（核心）：样式改名时改写所有控件的 `style` 引用（两种引用形态都改）；
   动作改名时改写所有控件/菜单项的 `action`。一次改名 = **一步撤销**。
2. **引用计数**：两个对话框每条卡片显示「被 N 处引用」／「没人引用」。
   → 用户能自己判断"这条能不能安心删/改名"；也让"连带更新了几处"有个可核对的数量。
3. **复制样式**（py880「复制主题做自己的配色」的最小落地）：卡片上加「复制」，以现有样式为初值
   建一条新名（`原名_副本`，重名则递增）。用户改配色时先复制再改，不动原样式。
4. **口径统一**：把 5 处「改名不会自动更新引用」的文案改成事实（见 §4），
   并销掉 `docs/ARCHITECTURE.md §8`「下一步候选」里已经做完的两项（多选、对齐工具条）。

### 非目标（本轮明确不做）

- **不做**：删除样式/动作时自动清引用（删了就是删了，但要**把引用数写在按钮提示里**让用户先看见）。
- **不做**：`.cgui` 新增任何字段（沿用现成的 `styles{}` / `actions{}`）。
- **不做**：改 `runtime/`（引用解析在 `runtime/src/core/cg_doc.c` / `cg_action.c`，本轮不碰）。
- **不做**：配色板 / 明暗翻转 / 主题调色板（见 §0 的否掉理由）。
- **不做**：控件 id 改名连带改 `action` 里可能含 id 的地方（`action` 存的是动作名不是 id，无此问题）。

### 验收标准（每条都要能失败）

| # | 验收 | 怎么验（会红的方式） |
|---|---|---|
| A1 | 改名后，`"style": "log"`、`{"use":"log","size":11}` 两种形态都指向新名 | 探针逐形态断言 |
| A2 | 改名后 `{"use":"log","size":11}` 的**覆盖字段不丢**（`size` 还是 11） | 探针断言 |
| A3 | 动作改名后，控件的 `action` 与**菜单项**的 `action` 都更新 | 探针断言（菜单项要真递归到） |
| A4 | 引用计数正确：数得对「两种样式形态」与「控件 action + 菜单项 action」 | 探针断言（含 0 引用 / 多处引用） |
| A5 | 一次改名 = 一步撤销（`undo` 回到改名前，含引用） | 代码路径：改名与引用改写**在同一个 `onApply` 里**（不是两次压栈） |
| A6 | 改名到**没人引用**的名字时，引用改写数是 0、不报错 | 探针断言 |
| A7 | `.cgui` 结构无新字段、往返恒等仍然成立 | `tools\check-format.bat`（含 5 个示例的恒等回写探针） |
| A8 | 复制样式：新样式字段与源样式**逐字段相同**，且源样式未被改动 | 探针/手测 |
| A9 | 界面文案不再出现"改名不会自动更新引用" | `grep` 全仓为 0 命中（除历史计划文件） |

### 关键设计决定（定了，理由在此）

- **引用改名做成"两张表共用一套遍历"**（`model/refs.ts`），不各写一份：两个对话框要的东西一模一样。
- **原地改引用**（`node.style = to` / `s.use = to` / `holder.action = to`），不重建对象：
  与工程里既有的编辑习惯一致（`patchStyle` 也是原地改克隆体），且**保住 JSON 键顺序**（往返稳定）。
- **改名与引用改写放在同一个 `onApply`**：一次操作一步历史（A5）。
- **只认"按名字引用"的语义**：比较时 `trim()`，但**写回的是用户输入的新名原样**。
- **计数口径 = 引用点数**（一个控件算一处、一个菜单项算一处），文案统一写「N 处引用」。
- **复制样式不复制引用**：新样式是独立的空引用，用户自己去指。复制只搬字段值。

## 5. 边界与异常清单

| 场景 | 预期行为 |
|---|---|
| 改成一个已存在的名字 | 对话框的**重名当场标红**已拦（S3/S4 不动这段），不会覆盖 |
| 改名时新旧名相同 | 提前 return（既有逻辑），不产生历史、不改引用 |
| 样式是三种形态里的"内联对象" | 不参与改名（它本来就没引用） |
| `style` 是字符串但前后有空格 | `trim()` 后比较；命中则写回新名原样（清掉空格） |
| 控件的 `action` 是空串 | 不计入引用数 |
| `menu`/`menubutton` 的嵌套菜单项 | 必须递归到（`flattenItems` 已递归） |
| 改名时引用它的那个控件同时被删了 | 不存在——改名与引用改写是同一次 `onApply`，看的是同一份克隆体 |
| 某个样式没人引用 | 计数显示「没人引用」，改名时返回 0，不报错 |

### 遗留（本轮明确不做 / 已知边界）

- 🟡 **删除样式/动作不代劳清引用**：只把「还有 N 处引用」写在按钮提示里让人先看见。
  理由：自动抹掉几十个控件的 `style` 不可逆，而用户可能是"先删、回头重建同名样式"。
- 🟡 **对话框的"接线"只有类型系统与截图兜底**，没有自动化：探针只覆盖 `model/refs.ts` 的纯函数。
  要补的话得给画布加一层组件测试（本工程目前没有），不在本轮边界内。
- 🟢 观测：`renameActionRefs` 也会改**树节点**的 `action`（`types.ts:68` 注释写"树节点不用这个字段"），
  那是"画布不会生成"的约定、不是"运行时忽略"，一起改只会让文档更一致。
- 🟢 观测：`countRefs` 在对话框每次渲染重算一遍全树（模态对话框 + 几十个控件，量级可忽略）。
