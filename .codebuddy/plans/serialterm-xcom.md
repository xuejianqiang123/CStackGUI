# serialterm 对标 XCOM：抄它的好用之处，用我们的强项反超

## 参照物（用户给的 XCOM V2.6 三张截图）逐条对表

| XCOM 有 | serialterm 原状 | 本轮 |
| --- | --- | --- |
| 16 进制显示 / 时间戳 / 自动保存 | ✗ 接收是纯文本 edit | ✅ 换 `terminal` 控件（框架本就带 hex/时间戳/方向着色/存盘） |
| 多条发送（分页表格 + 每行勾选 + 循环） | ✗ 只有单条 | ✅ 多行文本"一行一条" + 依次/循环 + 周期；**不做分页表格**（见下） |
| 定时发送 + 停止发送 | ✗ | ✅ 周期 ms + 停止 |
| 发送新行 | ✗ | ✅ 追加 `\r\n` |
| 打开文件 / 发送文件 | ✗ | ✅ 打开文件进"多条"框、文件内容原样发 |
| 保存窗口 / 清除接收 / S:R 计数 | ✅ | 保持（保存日志改走 `cg_term_save`） |
| 协议传输（正点原子私有 IAP 协议） | ✗ | **不抄协议**：那是厂商私有帧；我们给的是通用件 `cg_crc16` + `cg_modbus_*` + `cg_frame_*` |
| —— | —— | ✅ **按帧显示**（`cg_frame_*` 静默/分隔符切帧 + 每帧长度 + CRC16 结论）——**XCOM 给不了** |

## 为什么"多条发送"做成多行文本而不是 XCOM 的分页表格

画布里的 `table` 不支持**逐格编辑 + 每行复选框**（要改运行时控件能力，代价远大于收益）。
而现场真正要的东西是"一组命令按顺序、按周期轮着发" —— 这在多行文本里更省事：
粘贴十几行命令本来就是一整块文本，行首 `#` 当注释、空行跳过。**功能等价、交互更利落。**

## 交付

1. `examples/serialterm/serialterm.cgui`：接收区换 `terminal`；加显示开关（16 进制 / 时间戳 / 按帧 / 自动保存）；
   发送区分成"单条"与"多条"，加定时发送与文件按钮。
2. `examples/serialterm/main.c`：接收管线走 `cg_term_write`（三行代码顶掉原来手写的环形缓冲 40 行）；
   按帧显示接 `cg_frame_*`；发送侧加 `prepare_send()`（唯一一处"输入 → 字节"的转换，供单条/多条/文件/演示共用）。
3. `--demo`：**不开真串口**，把几批合成字节灌进接收管线，并把"切出的帧 / CRC 结论 / 发送侧解析出的字节"
   打到 stdout —— 端到端要有**能断言的文字**（截图只作辅证）。

## 验证判据

- `--selftest` 通过（合成触发每个回调，不许碰真硬件）；
- `--demo` 的 stdout：按帧显示切出的帧数、每帧长度、CRC16 结论，与喂进去的合成数据对得上；
- 发送侧：`prepare_send()` 对同一份输入的输出字节（HEX 解码 + 新行）在演示里逐字节打印。
