# Modbus 帧编解码（cg_kit_modbus.c）

## 为什么是它：方向怎么定的（第一性原理）

用户是**嵌入式 / 工控**方向，这套框架的用途是"工程师做 PC 侧上位机"。按他的工作循环逐项核过
框架的覆盖（**没有一项靠印象，都去代码里查了**）：

| 环节 | 覆盖 | 证据 |
| --- | --- | --- |
| 连 | ✓ | 串口组件 + `cg_net_*`（TCP/UDP） |
| 发 | ✓ | 动作 / 定时器 / hex·ASCII 转换 |
| 看 | ✓ | 终端已有**时间戳**（`cg_term_set_timestamp`）与 **hex 模式**（`cg_term_set_hex`） |
| 判 | ✓ | `cg_crc32` / `cg_crc16`(Modbus) / 进制与补码 / 字节序读写 / 字节集切片 |
| 记 | ✓ | 存盘 / 截图 / 剪贴板图片 |

⇒ 通用原料**已经齐了**（我原以为缺时间戳、缺校验，两个假设都被代码否掉）。
瓶颈在"从原料到一个能用的工控工具"之间那段**每个项目都要重写**的东西 = 协议帧编解码。
依据同样是仓库自己的文档：`docs/articles/09-校验与摘要.md` 当时正在**教用户手写**
`build_read_holding()`（自己摆字节序、自己挂 CRC）。

## 边界（有意不做）

- **不做主站事务**：轮询 / 超时 / 重试 / 多从站调度需要持会话状态，框架这一层不持运行状态。
- 不做协议特定的应用逻辑（那属于用户业务）。

## 验证方式：向量不靠记忆，靠第二份独立实现

写测试前先用一份**与 C 代码无关的 Node 实现**（5 行 CRC16/Modbus + 独立位打包）把每个
常量算出来。这一步**当场抓到我自己三个错**：

1. 以为规范里 `01 03 00 6B 00 03` 的 CRC 是 `76 87` ⇒ 实为 **`74 17`**；
2. 读线圈那条手算的 CRC `0C 84` ⇒ 实为 **`0C 27`**；
3. 0F 位打包第二字节手写成 `01` ⇒ 实为 `02`。

反证：`01 03 00 00 00 0A` → `C5 CD` 与文档手写帧**逐字节吻合** ⇒ 这份独立实现可信。
⇒ 结论：**"我以为的规范值"是假设，不是判据；凡是要写进断言的常量，先让第二实现算一遍。**
（项目里哈希的检验值早就是这么来的 —— 这次只是把它用到了协议常量上。）

## 结果

- 新增 5 套单测；整套 **111 套件 / 2753 断言 / 0 失败**，memcheck 111/111。
- 门禁：支持库 256 条（12 类）、分层 216 项 / 54 个 `.c`、文档口径一致。

## 配套示例（已交付）：`examples/modbus`

一个**工控向样板**：Modbus/TCP 上位机，`cg_modbus_*` + `cg_net_*`，界面在 `modbus.cgui`。

它担负的"验证"任务比"演示"更重：**不需要任何硬件就能把整条链在本机跑通** ——
配套 `mock-slave.mjs`（Node 模拟从站，实现 01/03/04 与异常码）。

**真机验证记录**（2026-09-27，跑的是 `build\verify_modbus.ps1`：起从站 → 演示模式跑示例 → 截图）：

```
[mock] 保持寄存器 0..9 = 100, 107, 114, 121, 128, 135, 142, 149, 156, 163
[mock] RX 00 01 00 00 00 06 01 03 00 00 00 08      ← 示例发来的读请求（tid=1、读 8 个保持寄存器）
[mock] TX 00 01 00 00 00 13 01 03 10 00 02 00 6B … ← 响应（tid 对上、长度 0x13、字节数 0x10）
[mock] RX 00 02 … / TX 00 02 …                     ← 轮询在跑，事务号递增
```

截图里表格的值（6 / 107 / 114 / 121 / …）与响应报文的字节逐字一致；状态栏"已连接 / 成功 4 / 失败 0"。

**这一片抓到的自己的 bug**：界面里终端被我**同时**开了 HEX 模式、又先编了一遍 hex 文本 ⇒
日志出现 `20 36 42`（正是字符 `" 6B"` 的 hex）—— **双重十六进制**，界面看着"有东西"但全是错的。
只有截图能看出来（值都对、就日志不对），已改成只用一个机制并在代码里写明"两个一起上会编两遍"。

**--demo / `CG_MODBUS_DEMO=1`**：启动就自动连本机模拟从站并开始轮询。
两个开关都认的理由：`tools\shot.ps1` 只会把 `.cgui` 传给 exe、没法再塞参数，环境变量会被子进程继承。
