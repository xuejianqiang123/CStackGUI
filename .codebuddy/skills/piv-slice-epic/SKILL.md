# 切片：大需求拆解为可交付单元

**输入**：$ARGUMENTS

将大需求拆成一组**每个都能独立实现、独立验证、独立提交**的小切片。

## 核心原则

- **每个切片 = 一次完整的 PIV 内循环**（prime → plan → implement → validate → review → commit）
- **切片越小越好**，一个切片交付后有可观察的行为变化（编译通过不算，行为变化才算）
- **依赖排序**：先做被依赖的（如先做协议帧解析，再做应用逻辑）
- **风险前置**：最不确定的部分最早做，尽早暴露风险

## 切片判断标准（不符合则继续拆）

一个合格的切片必须同时满足：

1. **可独立验证**：切片完成后有一个明确的验证方法（编译+行为测试）
2. **可独立提交**：不依赖其他未完成切片
3. **有行为价值**：切片交付后有可见的行为变化（新日志、新状态、新数据输出）
4. **规模合理**：大约 1-3 个源文件、或一个完整子功能

## 典型切片模式（本工程：Win32/GDI+ 工具包 + 画布）

- **纯逻辑层**：协议解析、校验、切帧、算法、状态机（可先做，用 `tools\run-tests.bat` 验证）
- **运行时能力层**：`runtime/src` 的 core / win32 / skin / kit 新接口（用单测 + `check-layers` 验证）
- **集成层**：把运行时能力接到控件/事件/动作上（`--selftest` 端到端，不需要真机）
- **界面层**：`.cgui` 与示例 App（`--selftest` + `tools\shot.ps1` 截图目视）
- **画布层**：`designer/` 的模型与导出（叠 `npx tsc --noEmit` + `npx vite build` + `check-format.bat`）
- **配置与文档**：`.cgui` 字段、类型表、事件表、`docs/`（动契约必须跑 `tools\check-format.bat`）

## 输出格式

在 `docs/` 下追加或新建切片清单，例如 `docs/SLICES_<feature_name>.md`：

```markdown
# 切片清单：<功能名称>

## 切片 1：<名称>
- 目标：<一句话>
- 涉及文件：<路径列表>
- 验证方法：<如何证明它工作>
- 依赖：无
- 优先级：P0

## 切片 2：<名称>
- 目标：
- 涉及文件：
- 验证方法：
- 依赖：切片 1
- 优先级：P1
...
```

## 完成后

- 输出切片列表供用户确认优先级
- 确认后，对每个切片依次运行 `piv-run-full-loop` 或手动走 PIV 内循环
