# 系统化调试（根因优先）

**输入**：$ARGUMENTS

来源：`obra/superpowers` 的 `systematic-debugging`（30.9 万★），删去其 TS/单测语境，
按本工程的 C11 + Win32/GDI+ + Electron 画布重写，并接上 `sop` §2A 的三段分离。

## 铁律

```
没有根因调查，不许提修复方案。
```

看到症状 ≠ 理解根因。**先能解释"为什么会这样"，再动手改。**

## 与 sop §2A 的关系

`sop` §2A 把修 bug 切成 **诊断 / 修复 / 验证** 三段，本技能是**第一段的执行体**：

| §2A 段落 | 由谁执行 | 产出 |
|---|---|---|
| 诊断（assess） | **本技能 阶段 1~3** | 根因 + 证据（不改代码） |
| 修复（fix） | `piv-implement` + `test-driven-development` | 单一修复 + 先失败过的复现测试 |
| 验证（test） | `piv-validate`（真窗口类叠 `serial_verify`） | verified / partial / failed |

## 阶段 1：根因调查（只读，不改代码）

- [ ] **读完整错误**：原文、行号、调用栈。不要只看最后一行，也不要先搜"怎么解决"。
- [ ] **稳定复现**：写出"预期 vs 实际 + 最小复现步骤"三件套（`sop` §2A 要求）。
      复现不了就先加取证，**不要靠猜改代码**。
- [ ] **查最近变更**：`git log --oneline -15 -- <相关路径>` / `git diff`。
      本项目多数"突然不对"是跨端契约或上次改动的连锁反应。
- [ ] **收证据**（按问题类型选）：

| 问题形态 | 本工程取证手段 |
|---|---|
| C 层逻辑 / 解析 / 切帧 | `tools\run-tests.bat` 跑现有单测；在 `tests/unit/` 加一次性断言比 printf 可靠 |
| 编译 / 链接失败 | 读**第一条**错误，不是最后一条；`--selftest` 起不来说明是链接期还是初始化期 |
| 运行时崩溃 | `--trace` 看最后一条日志；Win32 侧加 `GetLastError()` 值；GDI/句柄泄漏看对象计数 |
| 串口 / 网口丢字节 | 用假时间戳喂 `cg_frame_*`（不 sleep），或回环实测 |
| 界面画错 / 位置不对 | 截图比对；先用 `WM_GETFONT` 确认量文字用的字体对不对；查高 DPI 坐标换算 |
| 画布（`designer/`） | `npx tsc --noEmit` 报出的第一条；`.cgui` 往返探针 `tools\check-format.bat` |

- **完成判据**：能一句话说清"**什么条件**下、**哪一行**、**为什么**产生了这个症状"。

## 阶段 2：模式分析（找对照）

- [ ] 在仓库里找**同类正确实现**（同族控件、同类协议解析、同类 IPC 调用），逐点对比差异。
- [ ] 差异清单里只留**能解释症状**的那几条，其余记为噪音。
- **完成判据**：能指出"它和正确实现的差别只有 X，而 X 正好能导致这个症状"。

## 阶段 3：假设与验证（一次只改一个变量）

- [ ] 写成**单一假设**："我认为根因是 X，因为 Y（证据）"。
- [ ] 做**最小验证**：临时 printf / 一条断言 / 一个断点，验证 X 成立与否。
- [ ] 假设不成立 → **形成新假设**，不要在旧假设上叠加修复。
- [ ] 说不清就直说"我不理解 X"，继续取证，**不要假装懂了**。

## 阶段 4：实施修复

- [ ] **先写复现测试**（走 `test-driven-development`）：能变红，且失败原因就是这个 bug。
- [ ] 只改**已确认的根因**，一次一处；不顺手重构、不顺手改风格。
- [ ] 跑**全量** `tools\run-tests.bat`，不只跑自己那条。
- [ ] 交 `piv-validate` 验证**最初那个症状消失**（不是"我改的地方不报错了"）。

### 3 次修复失败 = 质疑架构

已试 3 次仍没修好，**停下**，不要再试第 4 次：

- 每次修复都在**不同位置**冒出新问题；
- 修复需要"大改"才能落地；
- 每次修好这里、坏那里。

这三条是**架构错了**的征兆，不是假设失败。此时交回用户，讲清"哪一层设计撑不住"，
走 `plan-architecture`，而不是继续打补丁。

## 本工程高频根因清单（先查这些）

1. **把"读一次"当"一帧"**：串口/网口只保证字节流，切帧一律 `cg_frame_*`。
2. **`%errorlevel%` 回显骗人**：cmd 解析整行时就展开了它；`| findstr` 后拿到的是 findstr 的码。
3. **GBK 管道里的中文 grep 恒空**：中文匹配一律回落到文件读取或 UTF-8 输出。
4. **在收字节线程里碰控件**：串口/网口线程只搬字节，控件不是线程安全的。
5. **句柄 / GDI 对象没配对释放**：`CreateXxx` 与 `DeleteObject` / `DestroyWindow` 必须成对。
6. **关窗时在回调里销毁控件**：先解绑，再销毁，否则回调打到已释放对象。
7. **高 DPI 下用的是物理像素**：坐标换算漏了缩放，位置对但大小不对（或反之）。
8. **量文字行高时 DC 没选控件字体**：`GetDC` 默认是 16px System 位图字体，量小了、居中就偏。

## 危险信号（出现即回到阶段 1）

- "先快速修一下，之后再调查"
- "大概是 X，我改了试试"
- "一次改多处，跑一遍看哪个生效"
- "跳过测试，我手动点一下就行"
- "已经试了两次，再试一次"
