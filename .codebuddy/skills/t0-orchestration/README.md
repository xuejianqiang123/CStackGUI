# T0 · 总控台（`t0-orchestration/`）

> 本目录**不是技能**，只是分组的壳：团队说明一律只写 `README.md`。
> 若在这里放 `SKILL.md`，技能扫描会停止下钻、把整团吞成一个技能，成员全部消失。

**使命**：拆阶段、排并行、控熔断与交付边界
**何时点将**：跨 ≥2 阶段、一条龙、多任务并行、要增删技能、故障要定位根因
**团长**：`sop`

## 成员（按上场顺序）

| # | 技能 | 一句话 |
|---|---|---|
| 1 | `sop` | CStackGUI 开发 SOP 总控（单一入口）：按请求类型路由到对应技能，串起「宪法→上下文→规格/计划→实现→验证→审查→提交→收敛」八段 |
| 2 | `piv-run-full-loop` | 端到端自动开发一个完整功能：加载上下文 → 制定计划 → 实现 → 验证 → 审查 → 提交 |
| 3 | `team-parallel-delivery` | 用「按文件域切分的并行小团队」交付中等以上规模的需求 —— 我 own 关键路径，队友 own 外围域（画布/示例/文档），契约先行、逐条回执、 |
| 4 | `skills-create` | 创建或更新一个 CodeBuddy skill（SKILL.md），遵循本项目 skill 规范 |
| 5 | `systematic-debugging` | 系统化定位根因（不猜、不试错堆补丁）——四阶段：根因调查 → 模式分析 → 假设验证 → 实施修复 |
