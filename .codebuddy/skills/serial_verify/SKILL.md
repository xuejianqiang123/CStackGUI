# 技能：真机行为验证（Runtime Behavior Verification）

**验证目标（可选）**：$ARGUMENTS

## ⚠️ 核心原则（验证的本质是"证明它真的那样动了"）

- **编译过 ≠ 工作**：`build-all.bat` 只证明语法和链接正确；`--selftest` 只证明"事件名字对得上、
  回调被调到了"（它**不开窗**）。真实的消息循环、焦点、按键、收发字节，这三样单测都照不到。
- **观察真实输出**：以**控件里的字节**（`terminal` / `edit`）、**程序自己写出的文件**、**截图**
  为事实源，而不是靠读代码推断"应该没问题"。
- **先定判据再动手**：动手前写清"看到什么算通过、看到什么算失败"，否则只是在看热闹。
- **异常路径必测**：正常路径能过是最低要求；半包、坏帧、对端拔线、端口不存在才是 bug 高发区
  （本工程的收发全在 `runtime/src/kit/cg_serial.c` / `cg_net.c` 的读线程 + 环形缓冲里，
  `docs/COMM.md` 写了它们的取舍）。

## 触发条件

- `piv-validate` 进入第 3 级行为验证，且改动只能在真窗口 / 真链路上观测
- 改动涉及串口或网口收发、`terminal` / `edit` 日志视图、快捷键与焦点相关的交互
- 用户明确要求：跑起来看看、回环测一下、实测、收发确认

## 🔍 验证操作清单

### 第 1 步：确定验证判据（动手前必做）

先写清楚每条要验证的行为对应什么**可观测结果**：

| 验证项 | 触发动作 | 期望看到 | 判为失败 |
|--------|---------|---------|---------|
| 程序起得来 | 双击 / 命令行起 | 窗口出现，标题与 `.cgui` 一致，无对话框报错 | 闪退 / "找不到界面文件" / 弹错误框 |
| 收 | 对端发已知序列 | 日志视图里字节与发送侧**完全一致** | 丢字节、错位、乱码（先排除波特率/编码） |
| 发 | 界面里发已知序列 | 对端收到的一致；HEX 模式下按十六进制解析 | 多/少字节、HEX 解析错 |
| 快捷键 | 焦点在输入框里按键 | 动作被触发（**这是窗口级 keydown 做不到的那件事**） | 只在焦点不在输入框时才有效 |
| 断连 | 拔线 / 对端退出 | 回落成"未连接"态（led/状态栏），**不卡死**、可重连 | 界面冻结、崩溃、状态不更新 |

> 没有明确判据的"看了一眼"不算验证。

### 第 2 步：选一种实测形态（本工程有三种，按手头条件挑）

**A. 有真串口设备或对端** —— 用仓库自带的串口助手：
```bat
build-app.bat serialterm
examples\serialterm\serialterm.exe            :: 选端口/波特率 -> 打开 -> 收发
```
数据落在编辑框/日志视图里，**把收到的片段贴进验证记录**。

**B. 没有硬件** —— 用网口回环替代同一套收发链路（同一份代码形状，本机就能跑）：
```bat
build-all.bat
examples\netterm\netterm.exe    :: 一台开"服务端"监听，另一台用"客户端"连 127.0.0.1
```
串口的等价物是虚拟串口对（com0com 一类），但本机不保证装了 —— **不要假装测过**。
另外 `tests/unit/test_net.c` 就是"本机回环端到端"的单测形态，纯协议逻辑优先在那里验。

**C. 没有硬件也没有对端，但改动是界面/交互** —— 起真窗口 + 程序化驱动 + **读回程序写出的文件**：
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File build\accel-verify.ps1
```
这是本轮（动作层的快捷键）沉淀并实测过的形态，四步缺一不可：
1. `Start-Process` 起**真窗口**程序，等它活着；
2. **先确认目标窗口真的在前台**（`SetForegroundWindow` 常被前台锁拒绝 ——
   没确认就把"没测到"当成了"功能坏了"，本轮第一次跑就是这么假失败的）；
3. 发键/鼠标（`SendKeys("^s")`、`{F10}{DOWN}{ENTER}`）；
4. **读回程序自己写出的文件**断言行数与内容（不看回显、不信"应该触发了"）。
> 脚本写进 `build\`（gitignore 内，收尾不清理）。**临时 `.ps1` 里只用 ASCII**
> —— Windows PowerShell 5.1 按 ANSI 读 `.ps1`，中文会变成"引号没闭合"式的假语法错误。

看外观用截图：`tools\shot.ps1`（PrintWindow 优先，不怕被别的窗口遮住）。

### 第 3 步：正常路径实测

- 比对**实际收到的字节**与第 1 步的期望，把片段贴进记录，不要只写"正常"
- 收发两侧都要看：只看一边等于只验证了一半
- 状态栏 / led 这类"派生显示"跟着一起看（它们是 `cg_widget_set_text` 链路的末端）

### 第 4 步：异常路径注入（最容易暴露 bug 的一步）

| 异常类型 | 注入方法 | 应有的正确表现 |
|---------|---------|------------------|
| 半包 | 只发半个帧就停 | 不卡死、不误判为一帧完整数据；下一拍继续取 |
| 坏帧 / 超长 | 发 CRC 错的、或超长数据 | 拒绝并记日志，**不越界、不误动作** |
| 对端断连 | 拔线 / 对端进程退出 | 回落未连接态、可重连；**界面不冻结** |
| 端口/地址不存在 | 打开 `COM99` / 连未监听的端口 | 报错可读（日志 + 对话框），**不假成功** |
| 灌满缓冲 | 高速灌超 64KB | 按环形缓冲策略丢最老的（`docs/COMM.md`），不溢出 |

**判据**：异常下要"优雅降级"，不是崩溃 / 冻结 / 无限等待。任一条卡住界面即为失败。

### 第 5 步：收尾

- 记录里贴**真实片段**（正常 + 异常各至少一段），需要时附截图路径
- 关掉所有起起来的进程（`taskkill`），别让 exe 占着文件让下一次编译报 `Permission denied`

## 强制规范

1. **判据先行**：无期望结果，不开始实测。
2. **贴事实**：禁止只写"已验证通过"；正常与异常各至少一段真实输出。
3. **异常必覆盖**：涉及收发的改动，第 4 步至少覆盖"半包"和"断连"两项。
4. **失败追根因**：实测暴露的问题回到代码定位（配合 `communication_protocol_check`），
   不在探针脚本里打补丁掩盖。
5. **不越界**：验证脚本放 `build\`（gitignore），不要往 `examples\` / `apps\` 里塞探针文件；
   确实要在门禁目录里放反例探针时，**同一步内删掉**并在报告里说明（本轮加分层门禁时就是这么做的）。
6. **`--selftest` 不能代替本 skill**：它不开窗、不合成窗口级事件、不碰真实的收发链路。

## 与 PIV 工作流的关系

本 skill 是 `piv-validate` **第 3 级行为验证**的执行手段，专门补齐"编译过 → 真机跑过"这一环：

```
piv-validate
├─ 第 1 级 编译 + 静态检查（build-all.bat / git diff --check；改了画布叠 tsc + vite build）
├─ 第 2 级 静态分析 + 单测（tools\run-tests.bat / tools\check-format.bat）
└─ 第 3 级 行为验证 ──→ 【serial_verify】真机实测（本 skill）
                         --selftest / --trace → 正常路径 + 回环 + 异常注入
```

- 纯逻辑（JSON 解析、控件模型、事件名表）用 `tools\run-tests.bat` 就够，不必起窗口
- 驱动 / 通信 / 交互类改动必须真机跑本 skill
- 验证失败 → 回到 `piv-implement` 修复，配合 `communication_protocol_check` 定位协议层根因
