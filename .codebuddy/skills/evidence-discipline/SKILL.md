# 取证纪律

**待证命题**：$ARGUMENTS

> 来源：2026-10-17 从上游 ai-dev-kit（`D:\CPro\.codebuddy`）同步并适配到本工程
> （Win32/GDI+ 桌面工具包 + 画布；伪证据清单已换成本工程实测实例）。

本工程最贵的错误**不是逻辑写错，而是"以为验证过了"**——结论看起来有据可依，
实际证据根本不支持该结论。这类错误能通过评审、能过全部门禁、能写进报告，然后由别人
（或未来的自己）按错误结论继续改动。**本技能只解决一件事：让结论与证据之间没有缝隙。**

## 核心原则

1. **文档不是证据，是待证假设。** README / PRD / 注释 / 提交信息里的一切陈述，默认可信度为 0，
   直到被代码或机械判据确认。它们的价值是"告诉你该去查哪里"，不是"替你查过了"。
2. **证据强度决定结论强度。** 机械判据（门禁 / 单测 / 编译器）> 读代码 > 实测 > 文档转述。
   用低强度证据下的结论，必须在结论里**标明不确定性**，且不能作为后续动作的唯一依据。
3. **先证伪再证实。** 找反证的成本远低于把自己已经写好的结论找证据：先问"什么情况下这条结论是错的"，
   去查那个条件是否成立。

## 已实证的伪证据清单（本工程与同类工程都发生过）

| # | 伪证据形态 | 为什么是伪的 | 正确取证 |
|---|---|---|---|
| 1 | `grep -c 某标识符` 的计数，或文档里手写的"共 N 条" | **grep 不区分注释与代码**；手写数字没有来源。本工程实证：支持库条数文档写 202、真值 292（编译后的表才算数），而门禁全绿 | 数字真值取**编译后的产物**（如 `cstackgui.h` 汇总表），不数源码 |
| 2 | "文件/组件存在" ⇒ "功能已实现" | 文件可能是空壳、桩、或从未被登记调用 | **三段取证**：代码存在 → 已登记（控件类型进 `k_kinds`、动作进动作表、新 `.c` 进构建）→ 已接线（调用者存在且非零）。缺一段即"未实现" |
| 3 | "头文件声明了" ⇒ "功能可用" | 声明与实现可能名字漂移，只在**链接期**暴露 | 找同名定义；找不到即"声明必有实现"违规 |
| 4 | "全部门禁通过" ⇒ "改动没问题" | 门禁可能**扫不到那份代码**：① 改动在 `.gitignore` 目录 ② 新增文件没进构建 ③ 例外表把违规登记成了基线 | 先确认门禁的**扫描域包含改动文件**，再看红绿 |
| 5 | "命令退出码 0" ⇒ "它真的跑了" | 工具可能静默退出。本工程实证：`.bat` 编码错时 cmd 定位漂移、注释后半句被当命令执行，满屏 `not recognized` 但后续命令仍可能继续 | 看**关键输出标志**（`--selftest` 的用例行、`build complete` 类字样），不看退出码 |
| 6 | "测试全绿" ⇒ "覆盖到了" | 桩把逻辑短路 / 0 字节可执行文件 / 用例漏登记 / 断言写错方向 | **变异自检**：故意改坏被测逻辑，确认用例**会红**；红了才说明它是有效闸门 |
| 7 | "重构/迁移完成" ⇒ "行为等价" | 复制型迁移常丢口径（"迁移丢常量"且全绿，本工程与上游都发生过） | 对照旧版**逐字段/逐常量**实测；声明"仅注释/格式改动"时给**骨架等价证明**（词法剥离后逐字节比） |
| 8 | "文档写了 X 缺失/未移植" ⇒ 事实如此 | 文档腐化滞后于代码 | 按上表第 2 条三段取证；**文档与代码冲突时以代码为准，并回写文档**（`doc-truth-sync`） |
| 9 | "零调用者" ⇒ "死代码，删掉" | 可能是弱函数 seam、动作表/事件表/支持库表等**隐式接线** | 区分**真调用者**与**隐式接线面**（回调表 / 注册宏 / 动作 ID 表）后再判 |
| 10 | "中文 grep / 管道 / 编码转换后为空" ⇒ "不存在" | 本工程实证：GBK 管道里匹配中文**恒空** = 假通过 | 换编码或换判据，并**先构造一个必然命中的样本验证判据本身有效** |
| 11 | `cmd \| findstr x; echo %errorlevel%` 恒为 0 ⇒ "命令成功了" | cmd 在**解析整行时**就展开 `%errorlevel%`，打印的是**上一条命令**的退出码；`\| findstr` 之后的退出码是 `findstr` 的。本工程实测：门禁实际是红的（文档口径 9 处报错），回显却是 0 | 判定**读日志**（重定向到 `build\*.log` 再读文件），不信回显、不信管道末环退出码 |

> **共同模式**：第 1、5、10 条都是**"判据本身没被验证过"**。任何新用到的判据，
> 都要先问一句"**它出错时会红吗？**"（同 `piv-validate` / `serial_verify` 的纪律）。

## 取证动作清单（按命题类型，可逐条打勾）

**A. 判"某功能是否已实现"**
- [ ] 落位代码存在？（文件 / 函数）
- [ ] 已登记？（控件类型表 `k_kinds`、事件绑定表、动作表、支持库表、构建脚本）
- [ ] 已接线？（至少一个真实调用者，或在隐式接线面里）
- [ ] 被静态判据覆盖？（相关门禁/单测是否**扫到了这份文件**，而不是只扫到别处）
- [ ] 若结论是"未实现"：是**真缺**还是**故意裁剪**？查配置开关与既有决策

**B. 判"文档/旧结论有没有做某能力"**
- [ ] 那份文档的证据是代码还是注释？按上表第 1 条取证
- [ ] 文档写的数字/条数，有没有编译后的真值可对？
- [ ] 取证手段：看登记表与条件编译分支的源文件清单，不是全文 grep

**C. 判"两个说法哪个对"（文档冲突 / 需求与代码冲突）**
- [ ] 把两个说法各自拆成**可验证的子命题**
- [ ] 逐条按 A/B 取证，**先看代码与机械判据**，文档转述排在最后
- [ ] 找到真正的**仲裁规则**（哪份文档/哪张表被指定为权威）并确认它自身不与其他处打架
- [ ] 裁决后**回写**落后的那一方，否则同一冲突会反复出现（详见 `doc-truth-sync`）

**D. 判"这条结论我能拿去改代码吗"**
- [ ] 结论有**文件+行号级**证据吗？（只有结论没有定位 ⇒ 无法复核，不可作为改动依据）
- [ ] 证据是机械判据输出，还是我的记忆/推测？（记忆与推测不是证据）
- [ ] 若证据来自旧操作，**它还新鲜吗**？（代码可能已被后续改动推翻）

## 结论的写法（避免把不确定性藏起来）

- 有机械判据 ⇒ 直接给命令与结论（可复现）
- 只有读代码 ⇒ 给**文件:行号**，让人能一眼复核
- 证据不足 ⇒ **明说"未验证/证据不足"**，并给下一步取证动作；**禁止**用"应该/大概/看起来"充当结论
- 发现是别人的结论错了 ⇒ 给证据 + 落点，**不擅自改需求文档的事实陈述**（改文档见 `doc-truth-sync`）

## 与其它技能的关系

- `adversarial-review`：评审阶段的**角色分离**（挑刺/辩护/改进）；本技能是**推理阶段的证据纪律**。前者防止自我辩护，后者防止自我欺骗——两者失效模式不同，不能互相替代。
- `doc-truth-sync`：发现文档与代码冲突后的**回写流程**。
- `serial_verify`：真机侧的判据执行；本技能管"上机前该有什么证据才值得上机"。
- `piv-validate`：**"验收命令必须能失败"**就是伪证据表第 5/11 条的具体形态。

## 本工程实例

- 数字真值取编译后的：支持库条数以 `cstackgui.h` 汇总为准（文档手写数必漂）。
- 登记面：控件类型在 `runtime/src/core/cg_doc_kind.c` 的 `k_kinds`、画布侧 `KINDS`、支持库表三处，靠 `tools\check-format.bat` 兜一致。
- "编译挂了"先查示例 exe 是否被截图脚本的残留进程锁住——代码可能没问题。
- 判定门禁红绿：重定向读 `build\*.log`，不看 `%errorlevel%` 回显。
