# 按计划实现

**计划文件**：$ARGUMENTS

严格按照已确认的实现计划执行。**Inherit don't re-decide** —— 计划里定的就是实现的依据。

## 执行规则

### 1. 严格按计划走
- 按计划的步骤顺序实现，每个步骤完成后立即做该步骤的验证，不要攒到最后
- 不擅自添加计划外的功能、重构、优化（先记入"待办"，问用户或留到下个切片）
- 发现计划本身有问题时：暂停，说明原因，与用户确认后再调整计划

### 2. 编码规范
- 遵循 `.codebuddy/global-rule.md` 与 `firmware_code_style` skill 的规范
- 新代码风格与所在文件/组件保持一致
- 为可复用的逻辑补充头文件注释（函数职责、参数、返回值、错误码）

### 3. 本工程特别注意
- Win32 资源：窗口 / 句柄 / GDI 对象用完即还，别漏（参考 `error_handling_check` 的资源路径检查）
- 错误处理：每个可能失败的路径都要有处理（参考 `error_handling_check`）
- 内存：优先静态分配，明确 buffer 大小上限（参考 `memory_leak_check`）
- 收发与协议：串口 / 网口的字节流按帧切（`cg_frame_*`），参考 `communication_protocol_check`

### 4. 验证随行（Validation-First）
每完成一个步骤，执行该步骤的验证方法：
- 编译检查：`build-all.bat`（或 `build-app.bat <名字>`），确保无新增警告
- 行为验证：按计划中的验证方法执行
- 发现问题立即修复，不要带着已知问题继续写

### 5. 禁止"降判据换绿"
- 不得删测试、放宽期望值、改阈值来让门禁或测试变绿；
- 不得为让门禁通过而登记例外（例外是债务，须带理由 + 摘除条件 + 用户确认）；
- 同一判据连续失败 3 轮 ⇒ 熔断上报，停止猜测（模板见 `piv-run-full-loop`）。

## 步骤循环（每步重复）

1. 读取计划中的当前步骤
2. 确认涉及文件当前内容
3. 实现改动（小步、聚焦）
4. 执行该步骤验证方法
5. 记录结果（通过/失败+原因）
6. 全部步骤完成后，运行整体验证清单

## 输出

完成后报告：

- 完成的步骤与验证结果
- 所有改动文件列表
- 计划外改动（如有，必须说明）
- 遗留问题/未验证项
