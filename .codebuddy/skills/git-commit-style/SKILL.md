# Git 提交信息规范

**输入**：$ARGUMENTS

本项目所有提交信息必须使用「类型标签 + 模块标签 + 中文描述」的格式，
这是用户明确要求的规则（原话：`[新增][模块] xxx`）。

## 格式

```
[类型][模块] 一句话说清这次提交做了什么
```

- **类型标签**：`新增` / `修复` / `重构` / `优化` / `文档` / `构建` / `发布`
- **模块标签**：`运行时` / `画布` / `示例` / `构建` / `发布` / `文档` / `技能`，
  也可以用具体工程名（如 `hello`、`gallery`）或子模块（如 `事件模型`）
- 描述用简体中文、一行说清；一行放不下就空一行写正文，正文解释"为什么"而不是"改了什么"

示例：

```
[新增][运行时] 事件按控件特性分配，绑错会警告并在 selftest 中报错
[修复][画布] 便携版找不到 C 项目根，改用 PORTABLE_EXECUTABLE_DIR 自动识别
[文档][发布] 使用者说明补齐从双击 exe 到出 exe 的流程
```

## 流程/检查清单

- [ ] 确认仓库已初始化（`git rev-parse --git-dir`；没有就先 `git init`）
- [ ] **按逻辑分组分批提交**（运行时 / 画布 / 示例 / 构建 / 文档 / 技能 各归各类），不要一把梭塞一个 commit
- [ ] 提交前先验证：`build-all.bat` 全绿 + `tools\check-format.bat` 通过（画布改动加 `npx tsc --noEmit`）
- [ ] 不提交生成物：`build\`、`release\`、`node_modules\`、`designer\dist\`、各工程里的 exe / lib / build-app.bat（已在 .gitignore）
- [ ] 每条信息按 `[类型][模块] 描述` 写，提交后 `git log --oneline` 复查格式
- [ ] 提交是用户明确要求的动作才做，不要主动 commit

## 输出

Git 提交历史，提交信息形如 `[新增][运行时] xxx`。
