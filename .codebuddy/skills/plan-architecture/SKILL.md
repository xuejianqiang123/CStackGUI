# 架构设计（嵌入式系统）

**输入**：$ARGUMENTS（PRD 路径或功能描述）

设计并输出符合项目规范的嵌入式架构文档。

## 核心原则

- **先画模块边界，再写代码**：数据流、职责划分必须先清晰。
- **继承项目现有模式**：优先复用 components/ 中已有组件与驱动，不重复造轮子。
- **嵌入式硬约束先行**：内存、时钟、功耗、实时性决定架构，不是偏好。
- **接口先行**：定义好模块间 API 契约，实现可并行。

## 架构设计检查清单

### 1. 模块划分与数据流
- 新增哪些模块？归属哪个子项目（proj_c2l_mainboard_p4 / s3 / esp32_c2_slave）？
- 数据从哪来到哪去？（传感器→处理→通信→存储）
- 模块间接口函数签名（头文件契约）

### 2. 任务模型（如用 RTOS）
- 需要哪些任务？优先级如何？（参考 `rtos_task_check` 的最佳实践）
- 任务间通信：队列/信号量/事件组选择是否合理？
- 栈大小估算：局部大数组、结构体是否避免放任务栈？

### 3. 内存与存储
- RAM 预算：静态分配还是堆？哪些可放 Flash（const）？
- Flash/NVS：存储什么配置？key 命名？擦写寿命是否考虑？
- DMA 缓冲：对齐、cache 一致性（参考 `dma_cache_check`）

### 4. 外设与引脚
- 涉及哪些外设？GPIO 复用是否冲突？（参考 `peripheral_conflict_check`）
- 时钟源选择：是否引入新时钟域？功耗模式是否需要低功耗设计？（参考 `power_management_check`）

### 5. 通信协议
- 帧格式、状态机、超时、重传、校验（参考 `communication_protocol_check`）
- 错误处理路径：解析失败、超时、丢包的行为

### 6. 兼容与迁移
- 是否改动现有协议/存储结构？需要版本字段或迁移逻辑吗？

```markdown
- 模块职责与依赖关系

## 3. 详细设计

### 3.2 任务/中断设计
### 3.3 内存与存储设计
### 3.4 外设配置（引脚、时钟、DMA）

## 4. 关键流程
- 状态机、时序、异常处理

## 5. 风险与开放问题
```
