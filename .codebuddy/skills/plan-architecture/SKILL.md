# 架构设计

**输入**：$ARGUMENTS（PRD 路径或功能描述）

设计并输出符合本工程规范的架构文档（跨端：`runtime/` 的 C 层 + `designer/` 的画布层）。

## 核心原则

- **先画模块边界，再写代码**：数据流、职责划分必须先清晰。
- **继承项目现有模式**：优先复用 `runtime/src`（core / win32 / skin / kit）与 `designer/src` 已有的能力，不重复造轮子。
- **跨端契约先行**：`.cgui` 字段语义、控件类型表、事件绑定表都是"同一事实两份"的地方，动了必须两端同步（`tools/check-format.bat` 兜底）。
- **接口先行**：定义好模块间 API 契约，实现可并行。

## 架构设计检查清单

### 1. 模块划分与数据流
- 新增哪些模块？落在哪一层（`runtime/src` 的 core / win32 / skin / kit，还是画布侧 `designer/src`）？
- 数据从哪来到哪去？（`.cgui` → 文档树 → 运行时控件树 → 原生控件；业务回调 → 控件状态 → 原生同步）
- 模块间接口函数签名（头文件契约）

### 2. 执行模型（本工程）
- 谁在什么线程上跑？（画布侧主进程 / 渲染进程；C 侧消息循环与业务回调）
- 阻塞与回调的边界：原生消息循环里不许长阻塞（会卡界面）
- 状态归属：谁持有句柄（窗口 / 串口 / 网口 / 定时器），什么时候释放？

### 3. 内存与资源
- 缓冲上限：静态分配优先，明确每个 buffer 的大小上限（C 层惯例：调用方给缓冲，库不 malloc）
- 句柄与 GDI 对象：创建即配对释放（`error_handling_check` 查资源泄漏）
- 长生命周期对象（如进程内缓存的 WLAN 句柄）：明确归属与归还时机

### 4. 平台与依赖
- 依赖是否可接受：本工程铁律是**零新增链接依赖**（Win32 / WLAN / 蓝牙符号运行期取）
- 平台版本差异：老 Windows 上取不到符号时如何降级（如实返回失败，不假装成功）

### 5. 通信协议
- 帧格式、状态机、超时、重传、校验（参考 `communication_protocol_check`）
- 字节流切帧用 `cg_frame_*`，别手写（见 `docs/ARCHITECTURE.md`）
- 错误处理路径：解析失败、超时、丢包的行为

### 6. 兼容与迁移
- 是否改动现有协议/存储结构？需要版本字段或迁移逻辑吗？

## 输出格式

保存到 `docs/SDD_<feature_name>.md`（与项目现有 SDD 文档风格一致）：

```markdown
# SDD：<功能名称>

## 1. 概述
- 目的、范围、关联模块

## 2. 总体架构
- 模块图（ASCII/文字）、数据流
- 模块职责与依赖关系

## 3. 详细设计
### 3.1 模块接口（头文件契约）
### 3.2 任务/中断设计
### 3.3 内存与存储设计
### 3.4 外设配置（引脚、时钟、DMA）

## 4. 关键流程
- 状态机、时序、异常处理

## 5. 风险与开放问题
```
