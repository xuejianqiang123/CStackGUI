# 设计品味（去 AI 味 · 提升观感）

**对象**：$ARGUMENTS

来源：综合 `anthropics/frontend-design`、`pbakaus/impeccable`(craft-floor)、`Leonxlnx/taste-skill`(anti-slop)、
`nextlevelbuilder/ui-ux-pro-max`、`Owl-Listener/designer-skills`(visual-critique/ui-design)、`ibelick/ui-skills`(baseline-ui)、
`carmahhawwari/ui-design-brain` 八套设计技能，删去 web 专有部分（Tailwind/GSAP/CWV/hero/bento/marquee），
按本项目的两块真实设计面重写：**画布 UI**（`designer/`）与 **`.cgui` 产出的桌面 App**（Win32 + GDI+ `skin/`）。

## 适用边界（别越界）

| 事项 | 走哪个技能 |
| --- | --- |
| 改画布结构/字段/控件/事件/IPC | `designer-modify`（本技能只管**观感与交互品质**） |
| C 代码规范、注释、命名 | `firmware_code_style` |
| 只要功能正确、不管观感 | 不需要本技能 |

## 核心原则

1. **先读盘再动手**：不读使用场景就选配色/圆角/字体 = 用默认审美填坑，产出一眼 AI。
2. **反模式是黑名单，不是建议**：下面「AI 味黑名单」里的东西**默认不做**；只有需求明确点名才允许，且要能说出理由。
3. **质量地板不宣布**：对比度、间距节奏、状态齐全、键盘可达是**底线**不是卖点。地板之下的东西不许交付。

## 步骤 1：设计读盘（动手前，一行话）

动手前先用一行话声明，并据此决定后面所有取舍：

> **读作**：<给谁>在<什么场景>用<哪块界面>，语气偏<克制/饱满>，落在<哪套既有语言>。

- **给谁 / 什么场景**：桌面工具（长时间盯屏、鼠标+键盘、窗口可缩放）默认偏「克制、可扫读、密度中等」；
  展示型/开机自启小工具才允许更饱满。
- **它本来的样子**（本项目的既有语言）：Material 3 圆角 + 单一强调色（`--seed`），
  画布是 13px 密度的生产力工具，不是落地页。**任何新观感必须落进既有语言，另起一套就是失败。**
- 读盘读不出来再提问，**最多问一个**，且要给出你的默认倾向。

## 步骤 2：三个旋钮（把"设计意图"变成数字）

每个视觉决定都由这三个数说话，写在交付说明里：

| 旋钮 | 1–3 | 4–7 | 8–10 |
| --- | --- | --- | --- |
| `VAR` 变化度 | 完全对齐的栅格、无装饰 | 有主次、少量非对称 | 强非对称、破格 |
| `MOTION` 动效强度 | 只有状态切换 | 加有目的的过渡 | 编排式动画 |
| `DENSITY` 信息密度 | 宽松（阅读向） | 标准 | 密集（仪表盘/表格） |

**本项目默认**：画布 UI `VAR 3 / MOTION 2 / DENSITY 7`（工具类，稳定可扫读优先）；
`.cgui` 业务 App `VAR 4 / MOTION 3 / DENSITY 5`（除非用户点名要展示型）。
旋钮是**上限**：`MOTION ≤ 3` 就老实做静态，别半成品动效。

## 步骤 3：AI 味黑名单（默认不做）

**① 颜色**

- 纯黑 `#000000` / 纯灰。用带色相的近黑（本项目 `--on-surface #1d1b20`）。
- 紫→蓝色渐变、渐变文字、霓虹外发光、零偏移彩色辉光（那是装饰不是阴影）。
- 彩色底上放灰色字：**彩色表面上的次级文字要从该色或前景色派生**（降明度/调色相），不是抹灰。
- 一个界面多个强调色。强调色一处锁死（本项目 `--seed #6750a4`），别在状态徽章里冒出第二个亮色。
- 靠颜色单一通道表达状态：必须**再给文字或形状**（"● 已连接" 而不是只有绿点）。

**② 层次与容器**

- 什么都裹成卡片、卡片里再套卡片。
- 同尺寸「图标 + 标题 + 正文」三连卡片当版面结构。
- 每个标题上方都挂一个小号、大写字距拉开的标签（eyebrow）——**这是第一号 AI 签名**。
- 侧边色条（`border-left/right` > 1px）当装饰。
- 1px 描边 + 大软阴影同时上（阴影与描边二选一，否则是"幽灵卡片"）。
- 所有东西居中，没有明确的第一落点。
- 分隔线/网格线/状态圆点纯装饰（不承载信息就删）。

**③ 组件与状态**

- 等权按钮：没有 primary / secondary / tertiary 之分。
- 占位符当标签；错误只在顶部汇总不给字段级提示。
- 禁用控件不说为什么被禁用。
- 可预测的布局用转圈 spinner 而不是骨架/进度。
- 状态只做"成功态"：缺 hover / focus / active / disabled / loading / empty / error 里的任何一个。
- 彩虹徽章：每个状态一个不同亮色，无语义。

**④ 图标与素材**

- Emoji 或 Unicode 符号当图标（本项目画布用 `.glyph-*` 图标类，C 侧自绘走位图）。
- 手搓图标路径/描边。用既有图标集或既有素材。
- 背景图里自带文字（放大后与控件文字打架，看起来像渲染异常）——挑**无字图**。
- 图片拉伸不留比例、留白突兀（本项目按钮背景图是圆角裁切拉伸铺满，选图要按这个预期挑）。

**⑤ 文案（这一条最容易被忽略）**

- 营销黑话：赋能 / 无缝 / 释放 / 颠覆 / 下一代 / 极致。
- 同一个动作在一处叫"保存"、另一处叫"提交"、第三处叫"确定"。
- "点击这里"式链接文字（要写目的地）。
- 错误信息只说"操作失败"：必须**说清问题 + 怎么恢复**，用界面口吻，不道歉不作诗。
- 破折号堆砌式文案（—）、中黑点分隔符串（A · B · C）满屏。
- 假精确数据（99.99%、1234）当装饰；示例数据要标成示例。

## 步骤 4：质量地板（可验证的数值）

| 项 | 门槛 |
| --- | --- |
| 对比度 | 正文/占位符 ≥ 4.5:1；大字号（≥18px）、图标、边框、焦点环 ≥ 3:1 |
| 间距 | 4px 基数（4/8/12/16/24/32/48）；**同组内紧（4–8），不同组间松（≥16）** |
| 标题呼吸 | 标题**上方**间距 > 下方间距 |
| 层级 | 相邻层级视觉差 ≥ 1.5×；字号步进用 1.25 比率，常用不超过 4–5 档 |
| 正文字号 | 桌面 ≥ 12px（本项目画布基准 13px）；正文不要靠缩小字号塞内容 |
| 行宽 | 连续文本 45–75 字符（画布内的说明文字同理，超宽要换行或加容器） |
| 点选目标 | 桌面可点区 ≥ 24×24；关键操作 ≥ 32×32。视觉标记可以小，**热区不能小** |
| 动效 | 交互反馈 ≤ 200ms；只动 `transform`/`opacity`；入场 `ease-out`；尊重 `prefers-reduced-motion` |
| 圆角 | 一套到底（本项目 `--radius 14px` / `--radius-sm 9px` / 胶囊 `h/2`），不混第三套 |
| 阴影 | 有偏移 + 柔化模糊；颜色调向背景色相，不用纯黑投影 |
| 素材 | 细节对齐到栅格；允许有意的光学修正，但不许"看起来差 1px" |

## 步骤 5：两端落地（本项目特有）

**A. 画布 UI（`designer/`）**

- 颜色/圆角一律用 `styles.css :root` 变量（`--seed/--surface*/--outline*/--on-surface*/--radius*`），**不硬编码 hex**。
- 一屏内只有一个视线的第一落点（选中控件/主操作）。
- 每个可交互元素四态齐全：默认 / hover / focus / active / disabled；`focus-visible` 必须存在。
- 单一强调色：`--seed` 只服务"当前选择/主要动作"，其余用 surface + outline 分层。
- 交付前**必须截图看**（`tools\shot-canvas.ps1`），不要用"类型检查过了"当观感证明。
- 改完跑：`cd designer && npx tsc --noEmit && npx vite build`。

**B. `.cgui` 业务 App（Win32 + GDI+ `skin/`）**

- 既有语言：中性表面 `0xEFEFF1` + 圆角（`style.radius`，缺省 8 逻辑像素 × `app->scale`）；
  设了 `style.bg` 就是实心主题色，文字按亮度自动选黑/白。
- 布局对齐到同一套间距；**不要每个控件都贴边铺满**，组与组之间留气口。
- 原生控件由系统管输入/IME/无障碍 —— 别为了观感禁用原生能力换全自绘。
- 自绘控件必须有 hover / pressed / focus / disabled 视觉（状态来自 `hot`/`pressed`/`ODS_*`）。
- 新增观感要走既有通路（`cg_skin_*`），别在业务里硬编码颜色（业务只 `#include "cstackgui.h"`）。
- 验证：`build-app.bat <名>` + `--selftest` 返回 0 + 截图肉眼确认（GUI stderr 不可靠）。

## 步骤 6：桌面专属检查（web 技能里没有的部分）

- [ ] **键盘可达**：Tab 顺序符合视觉顺序；有默认按钮（Enter）与取消（Esc）；focus 环可见。
- [ ] **DPI / 缩放**：125%/150% 下不糊、不裁切、间距不塌（本项目绘制按 `app->scale` 放大）。
- [ ] **文字膨胀**：中文/英文/长串都试过；标签不因翻译变长而截断或撑破布局（不要给文字写死像素宽）。
- [ ] **数值排版**：表格/列表里的数字**右对齐**；需要对齐比较时用等宽数字。
- [ ] **窗口状态**：最大化 / 最小尺寸 / 高 DPI 下布局不破相；滚动区有清晰边界。
- [ ] **空/错/加载/无权限** 四种状态都有内容，且空状态给出**下一步动作**。
- [ ] **破坏性操作**有确认，且确认文案说清后果。

## 步骤 7：交付前机械自检（勾不动就别交付）

- [ ] 设计读盘写了？三个旋钮的数写了？
- [ ] 黑名单过一遍：纯黑 / 渐变 / 灰字压彩底 / 卡片套卡片 / 满屏 eyebrow / 侧边色条 / 等权按钮 / 占位符当标签？
- [ ] 对比度按上面的表算过（不是"看着还行"）？
- [ ] 间距是 4px 基数上的取值？组内紧、组间松？标题上间距 > 下间距？
- [ ] 交互元素四态齐全，且**截图看过**（不是只看编译通过）？
- [ ] 界面上每一句可见文字都复读过：无黑话、无自相矛盾、术语一致、错误信息给了恢复路径？
- [ ] 只有一个强调色、一套圆角、一套字体层级？
- [ ] 这次改动**顺手删掉了**至少一处装饰性冗余（镜像法则：出门前摘掉一件配饰）？

## 输出

1. **改了什么**：一句话 + 关键文件。
2. **设计读盘 + 三个旋钮**：一行。
3. **问题清单**：`位置 → 违反了哪条（黑名单/地板）→ 具体修法`，按「影响可用性 > 影响观感 > 纯装饰」排序。
4. **验证证据**：`tsc/vite` 或 `--selftest` 结果 + 截图路径（`build\shot.png`）。
5. 评审类任务（只看不改）把清单落到
   `.codebuddy/design-reviews/<日期>-<范围>.md`，格式同上，末尾给"必须改 / 建议改 / 可以不管"三档。

**报告一句话版**：「按读盘 X 调了 A/B/C（旋钮 a/b/c），修了 N 处 AI 味与 M 处地板问题，截图 `build\shot.png`。」
