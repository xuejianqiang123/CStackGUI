# T1 · 需求与方案团（`t1-requirements/`）

> 本目录**不是技能**，只是分组的壳：团队说明一律只写 `README.md`。
> 若在这里放 `SKILL.md`，技能扫描会停止下钻、把整团吞成一个技能，成员全部消失。

**使命**：把模糊请求变成可执行规格与方案
**何时点将**：新功能、大需求、需求不清、架构选型、PRD/SDD/切片、方案会诊
**团长**：`request-spec`

## 成员（按上场顺序）

| # | 技能 | 一句话 |
|---|---|---|
| 1 | `request-spec` | 请求规格化——把模糊请求补全为可执行的七元规格（角色/任务/素材/结构/格式/约束/交付场景）后再动手，避免"猜需求 → 返工 / 虚构 / 越 |
| 2 | `plan-create-prd` | 将模糊需求澄清为可执行的 PRD（产品需求文档），输出到 docs/ |
| 3 | `plan-architecture` | 基于 PRD 做架构设计，输出 SDD（软件设计文档）到 docs/ |
| 4 | `piv-slice-epic` | 将大型 PRD/史诗需求拆解为可独立交付、可验证的小 ticket（切片） |
| 5 | `multi-perspective-review` | 多视角专家评审（三视角会诊方案）——分别以资深架构师（结构/演进）、资深 Win32 桌面开发工程师（落地/资源）、资深系统专家（失效面/可靠性 |
