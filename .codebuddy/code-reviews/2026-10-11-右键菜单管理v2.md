# 审查报告：注册表删值/删键 API + toolbox 右键菜单管理 v2

日期：2026-10-11　范围：`git diff HEAD`（runtime 两个新 API + kit 用例 + designer 支持库表 + 文档条数口径 + check-support 新门禁 + examples/toolbox 右键页 v2）
路由：`error_handling_check`（幂等契约与失败路径）+ `buffer_overflow_check`（命令行拼串 / 子键缓冲）+ `firmware_code_style`（Doxygen、命名、cg_free 配对）。

## 三角色审查

### R1 挑刺（10 项候选，摘关键）
1. `cg_reg_del`：`RegOpenKeyExW(KEY_SET_VALUE)` 的**任何**失败都算"已达成"→ 键在但无写权限时假成功（契约写着"0 = 调用后一定不存在"）。
2. `RegDeleteTreeW` 到底删不删键本身？MSDN 只写"递归删子键与值"，契约却承诺"整键不存在"。
3. `rm_delete_row` 删键失败仍把备份记进 `s_rm_changed` → 标签"删键 1"与事实不符。
4. 「还原」的状态栏用"三目选格式串 + 两个实参"→ 编译器查不了非字面量格式串，将来改文案易留多余 `%d`。
5. 命令拼串：`rel[1200]` / `cmd[2600]` / `cmd[1400]` 是否够。
6. 备份路径落在 `%LOCALAPPDATA%`（可能含空格），`reg export` 的引号是否配齐。
7. 空串护栏：`cg_reg_del_key("")` 必须挡住（`RegDeleteTreeW(HKCU, NULL)` 会删掉整个 HKCU 子树）。
8. 破坏性操作用 `cg_dialog_open` 而非 `cg_message_box`（后者无返回值，分不清点了哪个）。
9. 确认框文案靠 `cg_widget_set_text(cg_find(app,"edt_rmc_text"))` 注入 → id 绑定错就静默失效。
10. 每次操作后 `rm_scan` 重填表 → 选中被清空，同一行连做两次操作要重新点。

### R2 辩护（反证）
1. **立住**（见 R3）。
2. 驳倒：kit 用例断言 `cg_reg_subkeys(父键)` 只剩 `beta\n`（枚举不做任何过滤，空键也会被列出）；真机删除后表格 7 → 6 行、该行整条消失而非变"无命令" → 键本体确实没了。
3. 降级为观测：失败可能发生在"已经删掉一部分子键"之后，此时保留备份路径正是唯一的救回手段；且状态栏当场写明"删除失败（备份仍留在 X）"，表格里该项也还在 → 保留现状（救回可达 > 标签精确）。代价是极端失败路径下"删键 N"会多算一项，已记录。
4. **立住**（见 R3）。
5. 驳倒：`sub ≤ 512`（`rm_scan` 里 `char sub[512]`），`rel` 加前缀 5 字节、`cmd` 再加备份绝对路径（AppData 约 60 + 文件名 ≤ 96）→ 1200/2600/1400 均有 2 倍以上余量。
6. 驳倒：拼串已带引号；真机实测在含空格路径下导出成功（生成 `rmenu-20261011-170010-0.reg`，450 字节）。
7. 已测：kit 用例 `cg_reg_del_key(NULL) == -1 && cg_reg_del_key("") == -1` 通过。
8. 驳倒：真机跑通"确认 → 删除"与"取消 → 保留"两条分支（`cg_dialog_open` 返回 1/0 可辨）。
9. 驳倒：真机截图里对话框标题为"确认删除右键菜单项"、确认钮文案为"备份并删除"、正文带完整子键路径 → 动态注入生效（`.cgui` 里的 id 就是 `edt_rmc_text`）。
10. 降级为观测：本轮**否掉了**"给 runtime 加 `cg_table_select` 以保住选中"的提案 —— 判据：① 一门菜单项一个操作，删/禁用完自然要换下一行，只有"同一行连做两次"才受影响；② 免选中的撤销路径已经存在（「还原本次改动」一次撤销全部改动，不看选中），所以不需要新 API；③ 为一个示例的次要便利加一个永久公共 API，主题不对。改为在界面文案里写明"每次操作后自动重扫"，并在真机上复看不再溢出。

### R3 只修立住的
- **修复 #1**：`cg_reg_del` 改为只在 `ERROR_FILE_NOT_FOUND` / `ERROR_PATH_NOT_FOUND` 时返回 0（"值必然不存在"），`ERROR_SUCCESS` 才进删除分支，其余（ACCESS_DENIED 等）返回 -1，并写明理由注释。
- **修复 #4**：「还原本次改动」的提示拆成 if/else 两条，格式串与实参各自配对。
- **门禁加固（本轮立住的第二类问题）**：文档里手写的"支持库 202 条"实测真值 292（差 90 条），而当时**所有门禁都是绿的** —— `check-examples.mjs --docs` 只兜课数/文章数/控件类型数，不兜这个数字。已在 `check-support.mjs` 加第 5 步：拿编译后的真实条数（`cmds.length`）比 `examples/教学使用说明.md` 里那句「支持库（N 条）」；并验证门禁会咬人（把文档改成 291 → 退出码 1，报文直接给出应改的值）。文档同步为 292。
