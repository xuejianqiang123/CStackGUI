# 审查报告：`_ui_events.c` 自动补桩（生成代码保留业务代码）

范围：`git diff HEAD` = `designer/electron/{main.mjs,merge-events.mjs}`（后者新增）、
`designer/src/{codegen.ts,bridge.ts,App.tsx}`、`docs/ARCHITECTURE.md`、`apps/README.md`。
`runtime/`、`.cgui` 字段、`examples/` **零改动**。

## 病是什么（本轮要治的东西）

画布新绑一个事件后重新导出：`<工程>_ui_events.h` 会重写（新原型 + 新的 `CG_BIND` 条目），
`main.c` 的 `k_bindings[]` 展开那个宏引用了新名字，而 `_ui_events.c` **被整份跳过**
→ 新回调没有实现 → **链接 `undefined reference`**。用户只能手抄一遍签名。

## 三角色审查

### R1 挑刺（每条附自证）

| # | 位置 | 等级 | 问题 | 证据 |
|---|---|---|---|---|
| 1 | `merge-events.mjs` `splitBlocks` | 🟢 | 认不出生成器形状时**静默不补桩**（返回 `same`） | `if (!parts.length) return { content: old, added: [], mode: "same" };` |
| 2 | `main.c` | 🟡 | 它的标记注释说"可以被画布重新导出"，而导出路径从不覆盖它 —— 本轮只**把注释改成事实**，没让它真能重新导出 | `main.mjs` 里 `if (f.name === "main.c" && existsSync(target)) skip` |
| 3 | 用户把回调**改名** | 🟢 | 老函数会留在文件里成为死代码 | 有意：**永不删用户的代码**（删了可能丢逻辑） |
| 4 | `namesIn` 的函数识别 | 🟡 | 用户若把签名写成 `static void on_x(`，严格正则认不出来 → 会**重复补一个桩** → `redefinition`（比漏桩更难查） | 原始 `FN_HEAD = /^void\s+/`；**已修**（放宽到容错 `static` 与缩进），用反例证明了修之前真的会红：`FAIL 没有为 on_ok_click 补第二个定义` |
| 5 | `codegen.ts` 的桶导入 | 🟢 | 改成 `./model.js` 是为了让**编译产物**能被 Node 直接 import（端到端探针要真跑 `generateC`）—— 单看源码会显得后缀多余 | 已有注释说明；`tsc --noEmit` + `vite build` 都过 |
| 6 | e2e 探针留下的工程 | 🟢 | `apps/probemerge/` 会留在工作区（含 exe） | `.gitignore` 的 `apps/*` 覆盖，不脏仓库；按 SOP「临时产物不清理」保留，方便复跑 |

## 本轮自己撞到的坑（值得记）

第一版的 `merge-events.mjs` 语法就是错的 —— 我在块注释里写了注释收尾那两个字符（想表达"生成器那份
注释的收尾紧贴着签名"），注释被**提前闭合**，剩下半句变成代码，未闭合的反引号一路吞到第 93 行。
探针第一跑就报 `SyntaxError: Unexpected identifier '$'`。

而这**正是 `tools\check-electron.mjs` 存在的理由**（它的文件头写着：2026-10-07 有过一次同款事故，
块注释提前闭合 → 画布开机即崩、而当时所有门禁全绿）。所以这个坑有两张网兜着：探针 + 那条语法门禁
（本轮新增的 `.mjs` 自动进网：门禁输出从 `2 个 .mjs` 变成 `3 个 .mjs`）。

## 否掉的项（不许省）

- **整份重写 + 区域标记保留**（py880 那种做法）：用户会加**标记之外**的东西（include / 全局变量 /
  辅助函数 / `#if` 块），整份重写的合并器认不出来 —— 丢掉就是丢用户的代码，而这个功能的全部意义
  恰恰是"不弄坏用户的代码"。要安全重写就得写个 C 小词法器，收益只是"刷新注释"（签名本来就固定不许改）。
- **让 `main.c` 也重新生成**：见 R2 #2。
- **删掉已经不再绑定的回调**：见 R2 #3。
- **`merge-events.mjs` 放进渲染进程**（App 里合并、再让主进程写）：那样得为它开一个"读任意文本文件"的
  IPC（安全面），而主进程本来就已经在读 `main.c` 判 `handwritten`、也在写这些文件，合并放在那里最顺。
- 自己提过又否掉的：把合并做成"逐字节 diff 用户改动再重放"（复杂且无法定义"用户的改动"）。
