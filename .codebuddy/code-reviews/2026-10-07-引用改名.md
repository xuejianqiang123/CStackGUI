# 审查报告：命名引用改名连带更新（命名样式 + 动作）

范围：`git diff HEAD` = `designer/src/components/{StyleDialog,ActionsDialog}.tsx`、
`designer/src/components/Inspector/{StyleSection,ActionSection}.tsx`、`designer/src/model.ts`、
`designer/src/model/refs.ts`（新）、`designer/src/styles.css`、`docs/{CGUI-FORMAT,ARCHITECTURE}.md`。
`runtime/`、`.cgui` 字段、示例**零改动**。

## 三角色审查

### R1 挑刺（每条附自证）

| # | 位置 | 等级 | 问题 | 证据 |
|---|---|---|---|---|
| 1 | `StyleDialog.tsx` `removeStyle` | 🟡 | **删除**样式仍会让引用悬空（本轮只堵住了"改名"这条路径） | `removeStyle` 只 `delete d.styles[name]`，不碰引用；按钮 tooltip 里写了「还有 N 个控件引用它」但照删 |
| 2 | `ActionsDialog.tsx` 同理 | 🟡 | 同上（动作） | 同上 |
| 3 | `model/refs.ts` `renameActionRefs` | 🟢 | 会改**树节点**的 `action`，而 `types.ts:68` 的注释写着"树节点不用这个字段" | `for (const { item } of flattenItems(node.nodes)) swap(item)` 对所有 `nodes` 一视同仁 |
| 4 | `StyleDialog.tsx` / `ActionsDialog.tsx` | 🟡 | 对话框的**接线**（`onApply` 里真的调了 refs）没有自动化验证，只有纯函数有探针 | 探针 `build\probe-refs.mjs` 只 import 了 `modeljs/model.js` |
| 5 | `countRefs(doc)` 在对话框每次渲染都跑一遍全树 | 🟢 | 输入框每敲一个字（字段是"每改一下落盘"）都会重算 | `StyleDialog` 的 `const styleRefs = countRefs(doc).styles;` 在函数体里 |
| 6 | 样式对话框**抬头那行**在窄宽度下从 `...覆` / `盖 }` 处折行 | 🟢 | 观感：一行字被从词中间劈开 | 截图 `build\canvas-styledlg.png`；该行本轮**未改动**，属既有问题 |

### R2 辩护

| # | 反证 | 结论 |
|---|---|---|
| 1/2 | **自动清引用是破坏性的**：用户可能是"先删掉、回头重建同名样式"，替他把几十个控件的 `style` 抹掉不可逆；而删除本身就是显式动作、后果已写在按钮提示里。真正难发现的路径（改名）已经堵住了 | **驳不倒**，但保留"只告知不代劳"这个决定，写进遗留 |
| 3 | 那条注释描述的是**约定**（画布不会给树节点生成 action），不是"运行时会忽略"。手写的悬空 action 一起改到新名，只会让文档更一致，不会更糟 | **驳倒**：无行为风险，不改 |
| 4 | 接线部分**是被类型系统兜住的**：`renameStyleRefs` 若没被调，探针查不出来，但"改完的引用数对不对"在截图里可核对；且这段代码只有 3 行、在同一个 `onApply` 里 | **部分驳倒** → 降级为观测，写进遗留 |
| 5 | `countRefs` 是一次 `walk` + 每节点 `flattenItems`，量级 O(控件数 + 菜单项数)；本工程最大示例 75 个控件。每键几百次数组访问，量级可忽略 | **驳倒**（降级为观测） |
| 6 | 与本轮改动无关（该行一字未动），且属布局观感、不在本轮边界内 | **驳倒**（降级为观测，写进遗留） |

### R3 改进

- 本轮没有需要修的项：三条 🟡 里两条是**有意的不代劳**，一条是**类型系统已兜住的观测**。
- 自查补做：**反例验证**。探针第一遍全绿不算证据，故意把 `refs.ts` 的 `trim()` 拆掉重跑，
  真的红了 4 条（`改名改了 3 处` 变 2、`带空格的引用也被改到` 变 `[ log ]`、`旧名不再被引用` 变 1、
  `新名被 3 处引用` 变 2），再还原复跑回到 ALL PASS —— 证明它不是恒真空转。

## 否掉的项（不许省）

- **上一轮推荐的「主题/配色可视化编辑器」整条砍掉**，理由与证据写在 `.codebuddy/plans/refs-rename.md §0`
  （颜色在示例里是少数派 9/26；全局替换有编辑器这条替代路径；"一键深色"治不了 README 那条缺口的根因

  画布与文档，属跨端 epic，不塞进一轮。
- **删除样式/动作时自动清引用**：见 R2 #1。
- **把 `refs.ts` 的遍历改成带索引的增量统计**：见 R2 #5，量级不划算。
- 自己提过又否掉的：把引用计数做成"状态圆点"（黑名单里"状态只靠颜色"），改成文字「N 处引用 / 未被引用」。
