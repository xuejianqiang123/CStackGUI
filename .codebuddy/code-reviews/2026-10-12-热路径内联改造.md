## 改动内容
把 3 个跨编译单元的热路径小函数从 `cg_win_util.c` 搬进 `cg_win_internal.h` 按
`static inline` 定义（`-O2` 无 LTO 时跨 TU 永不内联，每次调用都是真实 call/ret）：

| 函数 | 调用重定位（改前→改后） | 依据 |
|---|---|---|
| `cgw_is_t` | 97 → 0 | 调用点最多，每条子控件消息/绘制都走 |
| `cgw_to_colorref` | 37 → 0 | 1 行纯表达式，12 个绘制文件使用 |
| `cgw_scale_px` | 53 → 0 | 纯算术，布局/同步路径高频 |
| 合计 | **187 → 0** | `objdump -dr` 重定位实测 |

函数体与原版本**逐字节一致**（diff 已核对），行为零变化。

## 审查发现

审查通过，未发现技术问题。

逐项核对：

1. **正确性**：三个函数体原样搬移；`RGB`/`strcmp` 所需头（`windows.h`/`string.h`）
   在 `cg_win_internal.h` 搬移点之前已包含；29/29 示例 selftest + 2178/2178 注释门禁
   + 全量单测（`-O2` 与 `-O1 -g` 两种构建）全绿。
2. **取址安全**：改造前 grep 确认三个函数在全仓无任何 `&函数名` 取址点，
   `static inline` 化不会破坏函数指针表。
3. **头文件 inline 后无外部引用残留**：全 58 个 runtime 目标文件
   `IMAGE_REL.*cgw_(is_t|to_colorref|scale_px)` 重定位数 = 0，链接全通过。
4. **体积门槛**：`.text` 251992 → 254580 B（**+1.03%**，门槛 ≤5%）。
5. **调试符号**：`-O0 -g` 实编探针确认——使用这些函数的 TU 均生成可断点的
   局部符号（`cg_win_util.o` 有 `cgw_is_t`/`cgw_to_colorref`，`cg_win_sync.o`
   有 `cgw_scale_px`）；无优化构建不内联，断点/步进不受影响。
6. **异常处理**：runtime 纯 C，无 try/longjmp/SEH（全仓 grep 0 命中），无变化面。
7. **行尾**：改动文件 100% CRLF（LF-only = 0），无混合行尾。
8. **`cgw_brush_for` 被正确排除**：函数体含 `static` 局部缓存，头文件化会
   按 TU 复制缓存（GDI 画刷重复创建、破坏"共享缓存勿删"契约）——一票否决，
   本次未纳入名单。

### [low] 规范偏离说明（有意为之，非缺陷）
- 文件：`runtime/src/win32/cg_win_internal.h`
- 问题：`firmware_code_style` §3 写"头文件只放声明/类型/宏，实现进 .c"，
  本次把 3 个小函数实现放进了头文件。
- 详情：这是本改造的目的本身——跨 TU 内联只有两条路：头文件 `static inline`
  或 `-flto`（后者会改变整个链接产物与调试面，已否掉为二期备选）。
  函数仍为后端私有（`cg_win_internal.h` 不进 `cstackgui.h`，业务代码不可见），
  分层门禁 `check-layers.mjs` 301 项全过。
- 结论：记录为**有理由的偏离**，不修。
