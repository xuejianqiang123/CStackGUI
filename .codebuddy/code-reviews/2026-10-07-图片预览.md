## 真机验证抓到的 bug（静态门禁全绿也照样不工作）

`useImage` 的请求 effect 原来只依赖 `src`。**React 的子组件 effect 先于父组件跑**：
首次渲染时 App 还没把基准目录（`filePath`）交给缓存，`requestImage` 带着空 base 直接返回；
等 App 那个 effect 补上 base 时 `src` 并没有变 —— 于是**再也不会重试**，六张图全停在"没读到"。
`tsc --noEmit` 与 `vite build` 全绿，`check-format` 也全绿，只有真机截图 `build\canvas-img2.png` 露了馅。
修法：请求 effect 依赖 `[src, version]`（缓存广播会让 version+1，于是带正确的 base 重试一次；
已读完的命中缓存直接返回，不会成环）。

## 否掉的项（不许省）

- **在画布上复刻"缺图占位框"的像素级外观**（运行时 `image` 画虚线框 + 文件名、`iconbutton` 画灰框 +「图标」、
  `button` 静默回退纯色）：画布要的是**在编译之前**发现问题，所以统一写「读不到 + 文件名」，故意比运行时显眼。
- **把透明像素压平成白色以"忠于"真机**：运行时确实不做 alpha 合成，但画布压平透明更误导
  （用户要看的是"这张图长什么样"）。改成"按真透明显示 + 界面与文档都写明差异"。
- **用 `<img src="file://...">` 直接引磁盘图**：dev 模式页面是 `http://localhost:5273`，读不了 `file://`；走 IPC 两种模式都能跑。
- **给"太大"单独做一个状态**：见 R2 #1。
- **顺手做"图片热更新"**：见 R2 #2，是独立一轮。
- 自己提过又否掉的：把 `useImage` 留在 WidgetView 里从组件模块 export 给 Canvas 用（hook 出在组件模块里味道不对，挪进 `imagecache.ts`）。
