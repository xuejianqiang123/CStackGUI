# 环境与配置快照：懒加载的树，展开才采集

> 目录 `examples\envsnap\`　编译 `build-app.bat envsnap`　运行 `examples\envsnap\envsnap.exe`　自检 `envsnap.exe --selftest examples\envsnap\envsnap.cgui` → 控件 10 个 / 回调 5 次 /（未登记·事件不支持·绑定出错·动作出错·样式引用失效 全 0）→ `selftest OK`

## 一、它演示什么
重点是**懒加载的树**：左侧只先建两个根（环境变量 / 用户数据目录），**点开哪个才枚举哪个** —— 用户数据目录可能几百上千个文件，一次全展开会把消息循环堵住、界面假死，这和资源管理器「展开才读」是同一个道理。补的能力面是「树的懒加载 + 环境变量与目录的只读快照」。
为什么不做「注册表浏览器」：运行时只提供按名读一个环境变量、注册表只有 HKCU 的字符串值读写，**没有枚举接口** —— 所以换成同方向的「环境与目录快照」，这条边界写在 `main.c` 文件头。

## 二、怎么用
1. 打开即可看到两个根（环境变量 / 用户数据目录）。点开某个分组才去采集它下面的条目。
2. 点树节点：右侧表格显示该节点的条目（变量值 / 扩展名分类 / 目录条目）；点展开才枚举下一层。
3. 点「重新采集」清空树与节点表，重扫用户数据目录并重建两个根。
4. 点「导出快照」把当前**已采集**的内容写成 UTF-8 文本；点「复制快照」把同一份送进剪贴板。
5. 状态栏报条目 / 目录数；终端每行一条采集与导出记录。
6. 命令行：`envsnap.exe`（自动找同名 `.cgui`）、`envsnap.exe xxx.cgui`、`--selftest`。

## 三、一屏总览
| 控件 id | 类型 | 干什么 |
| --- | --- | --- |
| `btn_refresh` / `btn_export` / `btn_copy` | button | 重新采集 / 导出快照 / 复制快照 |
| `tree_main` | tree | 懒加载树（展开才采集） |
| `sp_main` | splitter | 左右拖动分树与表格 |
| `tbl_items` | table | 名称 / 值或大小 / 备注 |
| `term_log` | terminal | 采集与导出记录 |
| `sb_main` | statusbar | 状态 / 条目与目录数 |

## 四、关键接口
`cg_tree_add` 加节点、`cg_tree_selected` 取当前选中、`cg_tree_clear` / `cg_tree_count` 清空 / 计数；`cg_env` 按名取一个环境变量；`cg_dir_list` 逐条枚举目录；`cg_dir_exists` 判是不是目录；`cg_file_size` 取文件大小；`cg_save_file_dialog` + `cg_file_write` 导出；`cg_clip_set_text` 复制快照。

## 五、容易踩的坑
- 懒加载的意义在于：不点开就不采集，避免一次全展开把消息循环堵住、界面假死。
- 运行时只提供「按名取一个环境变量」，**没有枚举环境变量的接口**，所以这里列一份常用清单。
- 注册表只有 HKCU、只有字符串值的读写，**没有枚举子键 / 列举值的接口** —— 「注册表浏览器 + 导出 .reg」这条路走不通，这也是本示例换题材的原因。
- 树展开 / 选中事件在自检里会被合成触发，里面不许读盘、不许弹框。
