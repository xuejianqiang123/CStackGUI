## 想知道什么，去哪看

| 想知道什么 | 看哪 |
| --- | --- |
| 某个控件支持哪些事件 | `docs/CGUI-FORMAT.md` **第 4 节**类型表的「支持的 events」列（与运行时 `runtime/src/core/cg_doc_kind.c` 的位掩码一一对应，`node tools\check-examples.mjs --docs` 会逐行回校） |
| 事件名怎么拼、回调里怎么读参数（坐标 / 键码 / 增量） | `docs/CGUI-FORMAT.md` **第 3 节** |
| 控件的完整字段（`text`/`rect`/`style`/`items`/`bind`… ） | `docs/CGUI-FORMAT.md` **第 2 节** |
| 本课（基础与容器）的每个控件怎么用 | `examples/lessons/lesson01_basics/lesson01_basics.cgui` + `main.c`；讲解见 `docs/articles/01-基础与容器.md` |
| **输入框**的真实演示（单行 / 多行 / 数值框 / 输入方式与校验 / 大小写转换） | `examples/lessons/lesson02_inputs/` —— `edit` 的三种形态与各字段都在那儿，且每个控件一个专用回调 |
| 全仓库控件总览（一屏看全） | `examples/gallery/` |

## 关于"一个控件绑一堆事件"

如果你是来找那种写法的：它的**代价**是回调里要自己按 `cg_event_name(ev)` 分流，
而且事件一多就没人看得懂。本项目的示例现在统一走"**一个控件一个专用回调**"，
只有两处例外（容器表单用一个 `on_form_change` 按 `cg_widget_id(self)` 分流；
同组单选共用一个回调）——两处的理由都写在各自 `main.c` 的注释里。
