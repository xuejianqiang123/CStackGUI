# 入门 01 · 按钮与输入框全功能说明

`lesson01_edit_button` 在最简骨架（输入框 + 按钮 + 标签）之上，把 **按钮（`button`）** 和
**输入框（`edit`）** 两类控件的**全部能力**都摆出来跑一遍。界面在 `lesson01_edit_button.cgui`，
行为在 `main.c`——这个例子里的每一行 C 都对应界面上能点/能看的某一块。

界面上都有什么：

| 区域 | 控件 id | 演示了什么 |
|------|---------|-----------|
| 左上 | `edt_name` / `btn_hello` / `btn_clear` | 最小骨架：读输入、改界面、回车=点按钮 |
| 上中 | `btn_full` | **按钮全功能**：背景图 + 13 种事件 |
| 中左 | `edt_events` | **输入框全功能**：15 种事件全绑一个函数 |
| 上右 | `edt_spin_auto` / `edt_spin_manual` | 数值框（`spin`）：自动夹取 / 手动自定义步长 |
| 中左 | `edt_byte` / `edt_int` / `edt_dt` | 输入方式：字节 / 整数 / 日期时间 |
| 中左 | `edt_upper` / `edt_lower` / `edt_max` | 大小写转换、最大长度 |
| 左下 | `edt_multi` | 多行 + 双向滚动条 + 单线边框 |
| 右侧 | `edt_b1` ~ `edt_b6` | 六种边框样式 |
| 底部 | `lab_result` / `sb_main` | 结果区与状态栏：所有回调都往这里写 |

# 一、按钮（button）

## 1. 背景图（`src` 字段）

按钮的 `src` 与图片控件（`image`）、图标按钮（`iconbutton`）共用同一个字段，由运行时按需加载，换图会自动释放旧位图。

```jsonc
{
  "id": "btn_full",
  "type": "button",
  "rect": { "x": 432, "y": 44, "w": 124, "h": 40 },
  "text": "按钮全功能",
  "style": { "fg": "#FFFFFF" },   // 图上文字用白色，深色图才看得清
  "src": "assets/icon.png"         // 相对 .cgui 所在目录
}
```

要点：

| 项 | 说明 |
|----|------|
| 支持的格式 | `png` / `jpg` / `bmp` / `gif`（gif 取第一帧，不播放） |
| 摆放方式 | **拉伸铺满**整个按钮，再裁进圆角里；不保持比例 |
| 路径 | 相对 `.cgui` 所在目录；找不到只警告，按钮照常画成纯色 |
| 文字颜色 | 默认按底色自动黑/白；设了 `style.fg` 就听你的（图上没法自动算对比度） |
| 没有 `src` | 就是一个普通主题色按钮，行为完全不变 |
| 与 `iconbutton` 区别 | `iconbutton` 把图**等比缩放到控件内**当图标；`button` 把图当**背景铺满** |

本例把 `examples/gallery/assets/icon.png` 拷到了 `assets/icon.png`，所以整个目录搬走也能跑。

> **挑图注意**：别用自带文字的图当按钮背景——运行时会把按钮的 `text` 画在图上，图里自带的字和它叠在一起，看起来就像「渲染乱了」。另外按钮的 `text` 留空时**运行时不会画任何文字**，如果你在空文字的图片按钮上看到了字，那一定是图片自己带的。

## 2. 按钮支持的 13 种事件

| 事件名 | 触发时机 | 回调里常用的取值 |
|--------|----------|------------------|
| `click` | 左键单击抬起 | — |
| `dblclick` | 左键双击 | — |
| `mousedown` | 左键按下 | `cg_event_x` / `cg_event_y`（相对窗口客户区） |
| `mouseup` | 左键松开 | 同上 |
| `rdown` | 右键按下 | 同上 |
| `rup` | 右键松开 | 同上 |
| `mousemove` | 鼠标在按钮上移动 | 同上；高频，建议只更新状态栏 |
| `gotfocus` | 按钮获得键盘焦点 | — |
| `lostfocus` | 按钮失去键盘焦点 | — |
| `keydown` | 键按下（焦点在按钮时） | `cg_event_key`（虚拟键码） |
| `keyup` | 键松开 | 同上 |
| `char` | 可打印字符键入 | `cg_event_key`（字符码，如 `'A'`） |
| `wheel` | 滚轮滚动 | `cg_event_delta`（正数=向上） |

取值 API（都在 `cstackgui.h` 里，参数传 `self` 即触发事件的控件）：

```c
int x   = cg_event_x(self);     // 鼠标 x（相对窗口客户区）
int y   = cg_event_y(self);     // 鼠标 y
int vk  = cg_event_key(self);   // keydown/keyup=虚拟键码，char=字符码
int d   = cg_event_delta(self); // 滚轮滚动量（正=上）；调节器 spin 事件=±1
int mod = cg_event_keys(self);  // 修饰键：1=Ctrl 2=Shift 4=Alt
const char *name = cg_event_name(ev); // 事件名字符串，如 "click"
```

## 3. 一个函数绑多种事件

13 种事件在 `.cgui` 里都填同一个名字 `on_full_event`：

```jsonc
"events": {
  "click": "on_full_event", "dblclick": "on_full_event", "mousedown": "on_full_event",
  "mouseup": "on_full_event", "rdown": "on_full_event", "rup": "on_full_event",
  "mousemove": "on_full_event", "gotfocus": "on_full_event", "lostfocus": "on_full_event",
  "keydown": "on_full_event", "keyup": "on_full_event", "char": "on_full_event",
  "wheel": "on_full_event"
}
```

C 侧用 `cg_event_name(ev)` 分流；高频的 `mousemove` / `gotfocus` / `lostfocus` 只更新状态栏，其余打到结果标签方便对照：

```c
static void on_full_event(cg_widget_t *self, cg_event_t ev, void *user)
{
    cg_app_t *app = cg_app_of(self);
    int x = cg_event_x(self), y = cg_event_y(self);
    int k = cg_event_key(self), d = cg_event_delta(self);
    (void)user;

    switch (ev) {
    case CG_EVENT_MOUSEMOVE:  /* 只动状态栏，不打扰结果区 */
    case CG_EVENT_GOTFOCUS:
    case CG_EVENT_LOSTFOCUS:
        /* ... set_status ... */ return;
    default: break;
    }

    char buf[160];
    switch (ev) {
    case CG_EVENT_CLICK:    snprintf(buf, sizeof(buf), "事件：click（左键单击）"); break;
    case CG_EVENT_KEYDOWN:  snprintf(buf, sizeof(buf), "事件：keydown（虚拟键码 %d）", k); break;
    case CG_EVENT_CHAR:     snprintf(buf, sizeof(buf), "事件：char（字符 '%c'，码 %d）", k, k); break;
    /* ... 其余事件类似 ... */
    }
    cg_widget_set_text(cg_find(app, "lab_result"), buf); // 内部会自己拷贝字符串
}
```

> 提示：`cg_widget_set_text` 内部拷贝了字符串，所以直接传栈上的 `buf` 即可，不用 `cg_str_dup`。

# 二、输入框（edit）

输入框的每一个属性都对应 `.cgui` 里的一个字段；改一个字段就能在界面上立刻看出区别
（右侧六个框就是同一件事只改了 `border`）。

## 4. 全部字段一览

| 字段 | 面板上的名字 | 取值 | 说明 |
|------|-------------|------|------|
| `text` | 文字 | 字符串 | 初始内容。多行用 `\n` 分行（见第 9 节） |
| `multiline` | 允许多行 | `true` | 允许多行，Enter 变换行 |
| `scroll` | 滚动条 | `1` 横向 / `2` 纵向 / `3` 双向 | 缺省 0 = 无滚动条 |
| `maxlen` | 最大长度 | 整数 | 最多能输入多少字符；缺省 0 = 不限制 |
| `conv` | 转换方式 | `1` 大写转小写 / `2` 小写转大写 | 缺省 0 = 不转换。**初始文字也会被转**（Windows 在写入时就转） |
| `input` | 输入方式 | `0`~`11` | 见第 6 节 |
| `border` | 边框 | `1`~`6` | 见第 5 节；缺省 0 = 本工程原本的圆角描边 |
| `spin` | 调节器 | `1` 自动 / `2` 手动 | 右侧上下箭头。**开了它就是数值框**：`value` 是真相、显示文本由它派生；见第 7 节 |
| `min` / `max` | 底限 / 上限 | 整数 | 数值框的夹取范围（缺省 0 / 100），箭头和手输都会夹。**只有设了 `spin` 才会写进 `.cgui`** |
| `style.align` | 对齐 | `left` / `center` / `right` | 文字对齐（`ES_LEFT`/`ES_CENTER`/`ES_RIGHT`） |
| `hint` | 提示 | 字符串 | 鼠标悬停的 tooltip（所有控件通用） |
| `style.font` / `size` / `bold` / `fg` / `bg` / `radius` | 字体与颜色 | — | 和其它控件一样 |

## 5. 边框（`border`）

| 值 | 面板上的名字 | 长什么样 |
|----|-------------|---------|
| 缺省 0 | 缺省（圆角描边） | 本工程原本的 2px 圆角灰边（`edt_name` 就是这个）|
| `1` | 无边框 | 什么都不画；**聚焦时会有一圈紫环**，否则用户看不出焦点在哪 |
| `2` | 凹入式 | 3D 内凹：上/左暗、下/右亮 |
| `3` | 凸出式 | 3D 外凸：上/左亮、下/右暗 |
| `4` | 浅凹入式 | 一圈 1px 浅灰细线 |
| `5` | 镜框式 | 内外两圈细线（像画框） |
| `6` | 单线边框式 | 一圈 1px 深灰细线（本例的多行输入框用的就是这个） |

边框画在**客户区之外**，所以输入框自己重绘（选中文字、滚动、光标闪烁）永远盖不掉它。
**聚焦时一律换成主题紫**，优先级高于边框样式——键盘用户必须看得见焦点在哪。

## 6. 输入方式（`input`）

除了「通常 / 只读 / 密码」这三种纯样式，其余档位**真的会管住输入**，规则分两步：

1. **按键**：只放行这类值可能出现的字符，其它字符直接吞掉（连 `char` 事件都不发）；
2. **失焦**：能解析就把值夹进类型范围并重写文本，解析不了就清空——**「没填」是合法状态，运行时不会弹窗**。

| 值 | 面板上的名字 | 允许输入的字符 | 失焦时怎么收 |
|----|-------------|---------------|-------------|
| `0` | 通常方式 | 任意 | 不动 |
| `1` | 只读方式 | 不能改（可以选中、可以复制） | 不动 |
| `2` | 密码输入 | 任意（显示成圆点） | 不动 |
| `3` | 整数文本输入 | 只有数字（`ES_NUMBER`） | 不动 |
| `4` | 小数文本输入 | 数字、小数点、开头的负号 | 解析不了就清空 |
| `5` | 输入字节 | 数字（无负号） | 夹到 **0 ~ 255**，解析不了清空 |
| `6` | 输入短整数 | 数字、开头的负号 | 夹到 **±32767**，解析不了清空 |
| `7` | 输入整数 | 同上 | 夹到 **±21 亿**，解析不了清空 |
| `8` | 输入长整数 | 同上 | 夹到 `long long` 全程 |
| `9` | 输入小数 | 数字、小数点、负号 | 解析不了就清空 |
| `10` | 输入双精度小数 | 同上 | 解析不了就清空 |
| `11` | 输入日期时间 | 数字、`-`、`:`、空格 | 形状得是 `YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM`，否则清空 |

界面上的 `edt_byte` 就是 **5（字节）**：敲 `300` 失焦会被夹成 `255`，敲字母失焦会被清空，
它的 `lostfocus` 回调 `on_byte_blur` 把"收干净之后"的值写进结果区，方便对照。

> 提示：这些校验只改文本、**不派发 `change`**（本工程的规矩：程序改文本不触发回调）。
> 业务想拿最终值，在 `lostfocus` 回调里读 `cg_widget_text(self)` 就行。

## 7. 调节器（`spin`）：数值框

给输入框右侧挂一列上下箭头，两种方式：

| 值 | 方式 | 行为 | 本例回调 |
|----|------|------|---------|
| `1` | 自动 | 点一下按 **±1** 改值并夹到 `min`~`max`；先派发 `spin`，值真变了再派发 `change` | `on_spin_auto`：把最新值报到状态栏 |
| `2` | 手动 | 运行时只报 `spin`（±1），**值一点都不动**，由业务在回调里自己改 | `on_spin_manual`：步长 **5**、区间 ±999（自动方式做不到） |

**开了 `spin`，这个输入框就是「数值框」**：`value` 是真相，界面上的文本由 `value` 派生。
于是它和滑块/进度条是同一套值语义 —— `cg_widget_value()` / `cg_widget_set_value()` 可用，
控件绑定时也是抄 `value` 而不是抄文字；`.cgui` 里写 `text` 对数值框不生效（写 `value`）。

两种方式都派发 `spin`，`cg_event_delta(self)` 给出 `+1` / `-1`：

```c
static void on_spin_manual(cg_widget_t *self, cg_event_t ev, void *user)
{
    int v = cg_widget_value(self) + cg_event_delta(self) * 5;   /* 自己的步长 */
    cg_widget_set_value(self, v);         /* 写值；文本跟着派生（写文本没用） */
}
```

手输数字走同一套：敲进去的字符按「整数」过滤，`value` 跟着变并夹到 `min`/`max`，
所以"程序写 42"和"用户敲 42"是同一个状态。`change` 事件仍然是"内容变了"的通用通知。

## 8. 输入框支持的 15 种事件

比按钮多一个 `change`/`submit`/`spin`，少一个 `click`：

| 事件名 | 触发时机 | 回调里常用的取值 |
|--------|----------|------------------|
| `change` | 内容被改变（每敲一个字都来一次） | 内容用 `cg_widget_text(self)` 读 |
| `submit` | 单行输入框里按回车 | — |
| `spin` | 右侧调节器被点（要有 `spin` 字段） | `cg_event_delta`（±1） |
| `mousedown` / `mouseup` | 左键按下 / 松开 | `cg_event_x` / `cg_event_y` |
| `dblclick` | 双击 | — |
| `rdown` / `rup` | 右键按下 / 松开 | `cg_event_x` / `cg_event_y` |
| `mousemove` | 鼠标在输入框上移动（高频，只建议更新状态栏） | 同上 |
| `gotfocus` / `lostfocus` | 获得 / 失去焦点 | 表单校验放 `lostfocus` 最合适 |
| `keydown` / `keyup` | 键按下 / 松开 | `cg_event_key`（虚拟键码） |
| `char` | 字符输入（中文输入法也走这里） | `cg_event_key`（字符码；中文是双字节码，`%c` 打不出来） |
| `wheel` | 滚轮 | `cg_event_delta` |

界面上的 `edt_events` 把这 15 种**全绑到 `on_edit_event`**，手法和按钮的 `on_full_event` 一样：

```jsonc
"events": {
  "change": "on_edit_event", "submit": "on_edit_event", "spin": "on_edit_event",
  "mousedown": "on_edit_event", "mouseup": "on_edit_event", "dblclick": "on_edit_event",
  "rdown": "on_edit_event", "rup": "on_edit_event", "mousemove": "on_edit_event",
  "gotfocus": "on_edit_event", "lostfocus": "on_edit_event",
  "keydown": "on_edit_event", "keyup": "on_edit_event", "char": "on_edit_event",
  "wheel": "on_edit_event"
}
```

> `change` 每敲一个字都会来一次，所以 `on_edit_event` 把它和 `mousemove` 一起归到"只写状态栏"。

## 9. 多行与滚动条

`edt_multi` 同时开了四样东西：`multiline` + `scroll: 3`（双向）+ `maxlen: 200` + `border: 6`。

```jsonc
{
  "id": "edt_multi",
  "type": "edit",
  "rect": { "x": 16, "y": 296, "w": 400, "h": 130 },
  "text": "第一行\n第二行\n\n多行输入框：Enter 换行，右侧和下方都有滚动条。",
  "multiline": true, "scroll": 3, "maxlen": 200, "border": 6
}
```

关于换行的规矩（新手最容易踩的坑）：

- **`.cgui` 里和 C 代码里一律写 `\n`**（LF）；
- 运行时在把文本交给 Windows 多行 EDIT 时，会自动展开成它唯一认识的 `\r\n`——
  直接给 `\n` 的话整段文字会挤成一行，看着像"换行没生效"；
- 反向也一样：从控件读回文本时会去掉 `\r`，所以模型、回调、存盘里始终只有 `\n`。

也就是说业务侧永远只管 `\n`，不用自己处理 `\r\n`。

# 三、怎么跑

```bat
build-app.bat lesson01_edit_button
```

不开窗自检（解析 `.cgui` + 把每个绑定的事件都真调一遍回调，本例是 29 个控件 / 35 次回调）：

```bat
examples\lesson01_edit_button\lesson01_edit_button.exe --selftest examples\lesson01_edit_button\lesson01_edit_button.cgui
```

双击 `lesson01_edit_button.exe` 也能跑（自动在 exe 旁边找 `.cgui`）。

上手可以按这个顺序玩一遍：

1. 在 `edt_name` 里输名字，按**回车**——和点「打招呼」是一回事（`submit`）；
2. 点 / 右键点 / 双击 / 滚轮滚 **`edt_events`**，再看结果区和状态栏（15 种事件）；
3. 在 `edt_byte` 里敲 `300` 或字母，然后**点到别处**——看失焦校验怎么收；
4. 点 `edt_spin_auto` 的箭头（±1、夹在 0~100），再点 `edt_spin_manual` 的箭头（步长 5）；
   也可以直接在框里敲数字 —— 数值框的值一样会跟上；
5. 在 `edt_upper` / `edt_lower` 里敲字母看自动转换；试着在 `edt_max` 里敲第 9 个字（敲不进去）；
6. 六个 `edt_b*` 挨个点一下——**聚焦时边框一律变紫**，这是键盘用户唯一的焦点线索；
7. 切到别的窗口再切回来，看 `gotfocus` / `lostfocus` 在状态栏上的变化。
