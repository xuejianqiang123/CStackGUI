# CStackGUI 教学示例使用说明

这套示例（`examples\lesson01_basics` ~ `examples\lesson06_window`）是一份**从零开始的学习路线**：
六课各讲一个主题，各用**一屏**把该主题的控件摆齐，各只写 100~400 行 C，都能独立编译、独立运行。
学完这六课，你就能自己用画布 + C 写出一个小工具。想直接看"大而全"的参考，跳到最后的
[学完之后看什么](#六学完之后看什么)。

> **每个示例目录下都有一份 `README.md`**（功能 / 怎么用 / 一屏总览 / 关键接口 / 踩过的坑）：
> 只想看某一个示例、不想翻这篇长说明时，直接开 `examples\<示例名>\README.md` 就行。

这一轮重做时定的三条取舍，也决定了文章与文档怎么写：

1. **每课只出现"本课主题"的控件** —— 想查某个控件长什么样、怎么读怎么写，翻对应那一课就有。
   课外的控件不会跑进来刷存在感（唯一例外是逐课都要用的 `label` 与 `statusbar`）。
2. **一屏看全**：宽 760 固定、高按内容，**不允许横向滚动、不允许控件重叠** —— 截图就是文章配图。
3. **界面上每个控件在 `main.c` 里都有对应回调或注释**：讲解与代码一一对应，没有"只给人看、代码里没有"的东西。

## 二、怎么编译、运行、自检

### 2.1 编译

```bat
:: 方式 1：全部编译 + 自动跑一遍自检（推荐第一次这么做）
build-all.bat

:: 方式 2：只编译某一课
build-app.bat lesson01_basics

:: 方式 3：在画布里打开这一课的 .cgui，按 F5（保存 → 编译 → 启动，一条龙）
```

刷新运行时库、编译、链接都由脚本处理；产物就在**课自己的目录**里：

```
examples\lesson01_basics\
  lesson01_basics.exe     <- 双击就能跑（界面文件就在旁边）
  lesson01_basics.cgui    <- 界面：用画布打开改，改完不用重编译
  main.c                  <- 业务：你要读、要改的就是这个文件
  lib\                    <- 运行时库副本 + 中间产物（整个目录拷走也还能自己重编）
```

### 2.2 运行 / 自检

```bat
examples\lesson01_basics\lesson01_basics.exe                       :: 双击也行
examples\lesson01_basics\lesson01_basics.exe --selftest examples\lesson01_basics\lesson01_basics.cgui
```

`--selftest` **不开窗**，只做三件事：解析 `.cgui` → 打印控件树 → 把每个绑定了回调的**控件**事件
**真的合成调一次**（窗口级事件只核对回调名有没有登记、不合成 —— 合出来会真关窗退出）。它是唯一能自动发现「事件名写错了」的手段（事件按名字查表，
不相等不报编译错），返回非 0 就说明有问题。末尾那行 `-- 结果: 控件 N 个, 触发回调 M 次 …`
就是本文档里那些数字的来源。

> 因为自检**不开窗**，回调里凡是有副作用的动作（写文件、弹框、连设备）都该先问一句
> `cg_app_has_window(app)`，否则自检会卡住或产生垃圾数据 —— 六课里凡有副作用的地方都这么写。

## 三、每课详解

### 入门 01：基础与容器（`lesson01_basics`）

**一句话**：把"搭界面"要用的控件一次摆齐 —— 这一课之后，其它四课都是在往这套骨架里填东西。

**界面**（12 类 / 30 个控件）：按钮（含一个**禁用态** `btn_disabled`）、图标按钮 `icb_run`、
标签 `lab_hello`、链接 `lnk_docs`、开关 `sw_notify`、徽章 `bad_count`、标签片 `tg_demo`、
分割线 `sep_line`、状态栏，以及三个容器：分组框 `grp_form`、容器块 `box_panel`、卡片 `card_note`
（容器里各放 2~3 个控件，演示**相对坐标**）。

**关键 API**：`cg_find` `cg_widget_text` `cg_widget_set_text` `cg_widget_set_enabled` `cg_status_set`

**三个要点**

1. **容器里的坐标是相对容器的**（`grp_form` 里的按钮写 `{x:8,y:36}`，不是窗口坐标）。
2. **徽章 / 标签片 / 分割线是"显示件"**：徽章一个事件都没有；标签片只有 `click`；分割线只用来分组。
3. **禁用态的示范只能用皮肤真正画得出的控件**：`button` / `checkbox` / `radio` / `switch` 四类
   （其它控件 `enabled: false` 后和启用态长得一模一样，别拿它们演示"禁用"）。

**动手改一改**

- 把 `btn_primary` 的文字改成你的名字，跑一遍（记得 `.cgui` 是运行时读的，不用重编译）。
- 给 `box_panel` 里的开关加一条 `hint`，鼠标悬停看提示。
- 把卡片 `card_note` 里的标签片挪出去，看它是不是立刻跑到窗口上（容器的子控件是"跟着容器走"的）。

### 入门 02：输入与选择（`lesson02_inputs`）

**一句话**：一个表单会用到的输入控件，每一种的"读"和"写"分别是哪个函数。

**界面**（11 类 / 55 个控件）：**输入框的三种形态** —— 单行 `edt_single`、
多行 `edt_multi`（`multiline` + `scroll`）、**数值框** `edt_spin_auto` / `edt_spin_manual`（`spin`）；
**输入方式档位** `edt_byte`（字节）/ `edt_int`（整数）/ `edt_dt`（日期时间）/ `edt_short`（短整数）；
转换 `edt_upper`（`conv` + `maxlen`）；**六种边框** `edt_b1`~`edt_b6`；
选择类：复选框 `chk_vip`（含**禁用态** `chk_locked`）、单选钮 `rad_stu/rad_emp/rad_other`、
下拉框 `cmb_city`、列表框 `lst_skill`、富文本 `rt_note`、日期 `dtp_date` / 时间 `dtp_time`、月历 `cal_pick`；
容器 `grp_user` 里再放一组（演示容器内相对坐标）。

**关键 API**：`cg_widget_text` `cg_widget_set_text` `cg_widget_value` `cg_widget_set_value`
`cg_widget_checked` `cg_widget_list_item` `cg_widget_id`

**三个要点**

1. **三种输入框其实是同一个 `edit`**：多行 = `multiline:true` + `scroll:2`；
   **带 `spin` 的就是数值框** —— `value` 是真相、显示文本由它派生，所以它用
   `cg_widget_value()` / `cg_widget_set_value()`，控件绑定时也是抄**值**而不是抄文字。
2. **`input` 档位由运行时的"按键过滤 + 失焦校验"把关**：非法字符连 `char` 事件都不发；
   失焦时能解析就夹到该类型的范围、解析不了就清空（"没填"是合法状态，不弹窗）。
3. **同组单选钮共用一个回调**（读 `cg_widget_checked()` 判断现在选中谁）；
   本课还演示了一次"**多控件共用回调 + `cg_widget_id(self)` 分流**"（`on_form_change`，
   6 个边框输入框 + 容器里 4 个控件共用）—— 省代码的写法，代价是 id 必须写清楚。

**动手改一改**

- 给 `edt_single` 加 `maxlen: 8`，再试试粘一段长文本进去。
- 把 `edt_upper` 的 `conv` 从 `2` 改成 `1`，看初始文本 `abc` 会变成什么。
- 在 `on_form_change` 里给 `edt_b5` 单独加一句状态栏输出，体会"分流"怎么写。

### 入门 03：数值与指示（`lesson03_values`）

**一句话**：一共就一个数，看看它能被显示成多少种样子。

**界面**（10 类 / 27 个控件）：滑块 `sld_level`、进度条 `prg_level`、圆环 `ring_level`、
仪表盘两个（270° 弧 `mtr_arc` / 半圆 `mtr_half`）、状态灯 `led_state`（会闪）、
评分 `rate_star`、分页 `pg_page`、按钮 `btn_reset`（程序写值）、**禁用态** `btn_off`、
以及两个对照标签：`lab_level`（C 拼串 `60 / 100`）与 `lab_sld_mirror`（**`.cgui` 里绑到 `sld_level`**）。

**关键 API**：`cg_widget_value` `cg_widget_set_value` `cg_widget_set_period`
`cg_event_delta` + `.cgui` 的 `bind`（见 `docs\CGUI-FORMAT.md` 第 2.8 节）

**三个要点**

1. **`change` 与 `release` 是两件事**：滑块拖动过程中 `change` 一直发，松手才发一次 `release`。
2. **控件绑定的活例子就在这一课**：`lab_sld_mirror` **一行 C 都没有**（不在 `k_bindings` 里），
   它跟着滑块走；而旁边的 `lab_level` 要显示 `60 / 100` 这种**拼出来的字符串**，只能写 C ——
   一对比就明白：**bind 只整份抄值，要加工还得写 C**。
3. **点滑块轨道 ≠ 跳到你点的位置**：点一下是"朝那个方向走一格"（量程的 1/10），
   要精确设值请拖拇指；而且**命中带是轨道那一条**，不是整个控件矩形。
   另外程序用 `cg_widget_set_value()` 改值**不会**触发 `change`（`btn_reset` 演示的就是这条）。

**动手改一改**

- 把 `sld_level` 的 `max` 从 100 改成 10，看 `pg_page` 与进度条的表现（分页按 `max` 出页码）。
- 给 `led_state` 改 `period`，让它闪得更急。
- 把 `bind` 换成绑到 `rate_star`，看标签变成几（**绑定的目标类型决定抄什么**）。

### 入门 04：数据与日志（`lesson04_data`）

**一句话**：装"一组数据"的控件，API 分成"加 / 清 / 数 / 读 / 选中"五类，记住这张表就不会找错函数。

**界面**（11 类 / 23 个控件）：顶部动作行（清空日志 / 保存日志 / **禁用态** 导出）、
左侧 `tabs` **四页**（列表框 `lst_items` / 树 `tre_dir` / 表格 `tbl_data` / 图表 `cht_line` + `cht_bar`）、
分隔条 `sp_main`、右侧终端 `term_log`、时钟 `tmr_beat`。

**关键 API**：`cg_widget_list_add/clear/item` `cg_widget_list_count` `cg_tree_add/expand/selected`
`cg_table_add_row/set_cell` `cg_term_write` `cg_chart_push` `cg_splitter_pos`
`cg_widget_set_period` `cg_status_setf`

**三个要点**

1. **表格的行勾选 / 行数值 / 行图标不是 `.cgui` 字段**，是运行时 API
   （`cg_table_set_checked()`、`cg_table_row_value()`、`cg_table_set_row_icon()`）；
   勾选变化发的是 `check` 事件，不是 `select`。
2. **没有"改一项"的 API**（只有加 / 清 / 数 / 读）：要改内容只能整表重建
   （复制出来 → 清空 → 按需要重新加回）。返回 `char*` 的都要 `cg_free()`。
3. **`splitter` 天生是"两栏"语义**：拖它只改**两块** —— 紧挨着的前一块 + 同一容器里的最后一块
   （吃余量），**夹在中间的兄弟只被平移**。所以一个 pane 只放一个控件，要放多个就先用容器包成一个。
   另外运行时**没有布局引擎**：拖大的一侧会留白、拖小的一侧不会让子控件跟着缩 ——
   这也是"pane 里放一个能伸缩的控件（终端、表格、画板）最省事"的原因。

**动手改一改**

- 给树加"删掉选中节点"，体会为什么必须整树重建。
- 表格加一列「备注」（`cg_table_add_row` 的 `cells` 顺序就是列顺序）。
- 让 `tmr_beat` 每次 tick 往 `term_log` 写一行带方向的数据，看终端的三色与时间戳。

### 入门 05：命令与图形（`lesson05_commands`）

**一句话**：同一个动作可以从**菜单栏、工具栏、菜单按钮**三处发起 —— 本课让它们最后都调同一个函数。

**界面**（11 类 / 23 个控件）：菜单栏 `menu_main`（文件 / 视图）、工具栏 `tb_cmd`（4 项）、
菜单按钮 `mbtn_more`、取色器 `cp_ink`（当画笔颜色）、按钮 `btn_draw_circle/rect/clear`
（含**禁用态** `btn_undo`）、画板 `cv_board`、外形框三个（矩形 / 圆角 / 椭圆）、图片 `img_logo`、
网页 `br_page` + 「载入示例页」按钮。

**关键 API**：`cg_menu_last_id` `cg_widget_value`（工具栏第几项）`cg_canvas_line/rect/ellipse/clear`
`cg_event_x/y` `cg_file_write` `cg_browser_navigate` `cg_clip_set_text`

**三个要点**

1. **一个动作只有一处实现**：菜单项、工具栏按钮、菜单按钮项最后都走同一个 `do_command()`，
   状态栏会写明"这次是从哪儿点的"—— 加一条命令只改一处。
2. **菜单项要写 `id`**：点了哪一项用 `cg_menu_last_id(self)` 认；不写 id 就只能拿
   `cg_menu_last_text()` 按文字判断，改文案就失效。工具栏没有 id，点中第几项读 `cg_widget_value()`（0 起）。
3. **画板（`canvas`）的绘制会被记录**：`cg_canvas_*` 画的图形在控件重绘时按序回放；
   鼠标坐标要用 `cg_event_x/y()` **减掉控件自己的 x/y**（那是"相对窗口客户区"的坐标）。
   另外 `browser` 不用联网也能演示：先 `cg_file_write()` 写一个本地 html，再 `cg_browser_navigate()` 打开它。

**动手改一改**

- 在菜单里加一项「视图 / 画三角形」，接到 `do_command()` 上（只需改 `.cgui` + 一处 switch）。
- 让画板支持拖拽画线（`mousedown` 记起点、`mouseup` 画线）。
- 给 `cp_ink` 换初始颜色，看新画的图形颜色跟着变（**已画的图形不会变**，因为颜色是绘制时记下的）。

### 入门 06：主窗口与窗口事件（`lesson06_window`）

**一句话**：前六课都在讲控件，这一课讲**窗口本身** —— 它的配置写在 `.cgui` 的 `app` 里，它的事件写在
`app.events` 里，它的"程序信息"写进 exe 的版本信息。

**界面**（6 类 / 13 个控件 + 一整套窗口配置）：顶部一个分组框显示**程序信息**（产品名/版本/作者/单位，
全部由 `cg_app_info()` 从 exe 版本信息读回）、一排窗口操作按钮（关于 / 居中 / 总在最前 / 隐藏 1 秒再显示）、
一张**窗口事件流水**列表、一个"演示拦下这次关闭"的勾选框、三格状态栏。
窗口本身还用到了 `.cgui` 里的 `center: true`、`escClose: false`、以及 `app.info` 的 8 个字段。

**关键 API**：`cg_app_info` `cg_win_center` `cg_win_set_topmost` `cg_win_show` `cg_win_set_pos`
`cg_win_set_size` `cg_win_set_state` `cg_cancel_close` `cg_tray_action` `cg_set_timer` `cg_app_has_window`

**三个要点**

1. **窗口也是一个"控件"**：伪控件 id 固定是 `__window`（头文件里 `CG_WINDOW_ID`），
   它的事件和控件事件共用同一套 `CG_BIND` 机制，回调签名也一样（`self` 就是窗口伪控件）。
   窗口事件一共 26 个：`ready` / `close` / `closequery` / `destroy` / `move` / `size` /
   `activate` / `deactivate` / `firstactivate` / `idle` / `tray` / `show` / `hide` /
   `mousedown` / `mouseup` / `rdown` / `rup` / `mousemove` / `dblclick` / `gotfocus` /
   `lostfocus` / `keydown` / `keyup` / `char` / `wheel` / `drop`。
2. **`app.info` 不是"给画布看的注释"，它真的进 exe**：编译时由画布生成的 `.rc` 落进
   `VERSIONINFO`（右键 exe → 属性 → 详细信息能看到），运行时用 `cg_app_info(app, "product")` 读回。
3. **自检不合成窗口事件**：`--selftest` 不开窗，所以 `ready` / `size` / `keydown` 这些不会被触发
   （那一课的自检只报 4 次控件回调）——**窗口事件只能真跑起来验**，这也是第六课的价值所在。
   另外：`idle` 触发非常频繁，**别在里面做耗时活**；`cg_set_timer()` 是一次性的，周期性任务要自己重挂。

**动手改一改**

- 把 `.cgui` 里 `border` 改成 `"dialog"`、`maximizeBox` 改成 `false`，看窗口边框与按钮组的变化（一行 C 都不用写）。
- 给 `app.events` 加 `"char": "on_win_char"` 之外的 `keyup`，对比按下与放开。
- 把 `chk_ask` 勾上再关窗口，看 `cg_cancel_close()` 是怎么把这次关闭拦下来的。

## 四、通用知识（每一课都用到）

### 4.1 一条程序的骨架

```c
#include "cstackgui.h"           /* 业务代码只 include 这一个头 */

static const cg_binding_t k_bindings[] = {
    CG_BIND("on_button_click", on_button_click),   /* 左：.cgui 里的事件名；右：C 函数 */
    CG_BIND_END
};

int main(int argc, char **argv)
{
    cg_app_desc_t desc = {0};
    desc.bindings         = k_bindings;
    desc.cgui_path        = "xxx.cgui";
    desc.auto_locate_cgui = 1;     /* 双击 exe 也能跑：自动在 exe 旁边找 .cgui */
    desc.on_ready         = on_ready;   /* 等价于 .cgui 里 app.events.ready */
    if (argc > 1 && strcmp(argv[1], "--selftest") == 0) return cg_app_selftest(&desc);
    return cg_app_run(&desc);
}
```

回调签名永远是：

```c
static void f(cg_widget_t *self, cg_event_t ev, void *user);
```

- `self` 触发事件的控件（不会为 `NULL`）；
- `ev` 事件类型（同一个函数绑了多个事件时用它区分，见入门 03 的 `change`/`release`）；
- `user` 用 `cg_widget_set_user()` 挂的业务数据，默认 `NULL`。

### 4.2 事件名错了为什么不报编译错

`.cgui` 里存的是**函数名字符串**，运行时按名字在 `CG_BIND` 表里查函数指针。
好处是画布和 C 代码彻底解耦（改界面不用重编译），代价是写错名字编译不报错 —— 所以：

- 运行时会在启动后**汇总弹一次**提示："这些事件不会触发"；
- `--selftest` 会以非 0 退出码报出来（这是 CI 里唯一能自动发现它的手段）；
- 画布「事件」页签的「代码」按钮能直接跳到 `*_ui_events.c` 里对应的函数。

想让某个控件支持哪些事件，看 `.cgui` 类型表（`docs\CGUI-FORMAT.md` 第 4 节）——
事件是按控件特性分配的：标签、进度条、状态栏**一个事件都没有**，只有树有展开/折叠。

### 4.3 排错：先看日志文件

发布版（`--release`）**没有控制台**，`printf`/`stderr` 用户一个字都看不到。所以：

- 运行时启动就开一份日志：`%LOCALAPPDATA%\<exe名>\app.log`（超过 256KB 轮转成 `.old`）；
- 致命错误（找不到 `.cgui`、格式错、建窗失败、崩溃）会**写日志 + 弹中文提示框**；
- 业务代码用 `cg_log(CG_LOG_INFO, "%d 项", n)` 往同一个文件里补记录。

**用户报"点了没反应"，第一件事就是让他把这个文件发过来。**

调试版（默认编译方式）带控制台，`printf` 直接可见，开发时更省事。

### 4.4 编译 / 验证命令速查

```bat
build-all.bat                              :: 编运行时 + 全部示例，并逐个跑 --selftest
build-app.bat lesson03_values              :: 只编某一课
build-app.bat lesson03_values --release    :: 发布版（无控制台，走日志）

:: 手动自检某一课

:: 仓库级门禁（改控件表 / 改 .cgui 字段后必跑）
```

## 五、常见问题

**Q：双击 exe 什么都没发生？**
按顺序找界面文件：命令行参数 → exe 旁边 → `exe目录\..\apps\<exe名>\`。都找不到就写日志 + 弹框。
打开 `%LOCALAPPDATA%\<exe名>\app.log` 能看到它试过哪些路径。

**Q：改了界面（`.cgui`），程序里没变？**
`.cgui` 是运行时读的 —— 确认改的是 exe 旁边那个文件；调试版控制台会打印实际读的是哪个路径。

**Q：事件不触发？**
先跑 `--selftest`。返回 5 就是"事件名在 C 代码里没登记"。另一种可能是**绑定的事件该控件不支持**
（比如给标签绑 `click`），启动时会警告。

**Q：`--selftest` 卡住不动？**
多半是某个回调里弹了消息框。所有会弹框的地方都要先 `if (cg_app_has_window(app))`。

**Q：点滑块轨道，为什么不是跳到我点的位置？**
Windows 原生轨道的规矩：点通道 = **朝那个方向走一格**（本工程取量程的 1/10），
要精确设值请拖拇指；而且**命中带是轨道那一条**，控件矩形内但离轨道较远的地方点了没反应。

**Q：拖分隔条，为什么中间那几个控件被裁掉 / 或者左边留出一片空白？**
因为运行时**没有布局引擎**：`splitter` 只改"紧挨着的前一块"和"同容器最后一块"的尺寸，
中间的兄弟只被平移；容器变窄也不会让里面的固定尺寸子控件跟着缩。
正确用法是**一个 pane 放一个控件**（要放多个先包成 `group`/`card`）。

**Q：中文在控制台里是乱码？**
控制台代码页问题，不影响界面和日志文件（文件里是 UTF-8）。

**Q：想要圆角 / 换配色，改了没效果？**
按钮、开关、勾选、输入框、滑块、进度条、圆环走 GDI+ 自绘，`style.radius` / `style.bg` / `style.fg` 生效；
列表框、树、表格、标签页、月历、下拉框是系统原生控件，不吃自定义外观（Win32 固有限制）。

## 七、实用工具详解

上面那张表是索引。这一节把 `examples\` 下每个工具**具体演示了什么、用了哪些接口、有意留了哪些简化**摊开写 ——
它们都是"能直接照着改"的完整程序，比教学课更接近真实工程。

### notepad（`examples\notepad`）
**它演示什么**：一个"真能用的工具"的业务怎么组织 —— 菜单分发、脏标记、状态栏刷新、文件读写、编码转换、INI 持久化、关闭前拦截与日志；「文件」菜单四条命令用动作实现，一处写清「文字 + 快捷键 + 回调名」，菜单项只写 action 引用。
**关键接口**：`cg_file_read` / `cg_file_write`、`cg_ini_read` / `cg_ini_write`、`cg_path_join` / `cg_path_name`、`cg_gbk_to_utf8`、`cg_clip_set_text` / `cg_clip_get_text`、`cg_save_file_dialog`、`cg_set_title`。
**容易踩的坑**：快捷键走加速键表，所以焦点在输入框里按 Ctrl+S 也能保存；`cg_str_format` 返回堆内存，而 `cg_widget_set_text` 只是拷贝一份、不接管所有权 —— 必须先落到变量再 `cg_free`；老文件字节不像 UTF-8 才走编码转换，否则中文全乱码。

### serialterm（`examples\serialterm`）
**它演示什么**：串口助手样板（16 进制显示 / 时间戳 / 定时发送 / 多条发送 / 文件发送），并用框架的"帧间静默"把字节流切成整帧、每帧单独一行并报长度与 CRC16 结论。
**关键接口**：`cg_widget_serial` / `cg_widget_serial_open`（配 `set_baud` / `set_format`）、`cg_serial_read` / `cg_serial_write` / `cg_serial_available` / `cg_serial_list` / `cg_serial_last_error`、`cg_frame_init` / `cg_frame_feed` / `cg_frame_take` / `cg_frame_tick`、`cg_crc16`、`cg_chart_push` / `cg_chart_set_range`。
**容易踩的坑**：自检会合成触发每个回调（包括数据到达），所以回调第一件事先判设备句柄是不是 NULL；打开失败别只报"失败了"，要取中文原因；读线程只搬字节、绝不碰控件（Win32 硬约束）。

### netterm（`examples\netterm`）
**它演示什么**：网口调试助手（客户端 / 服务端 / UDP 三种角色共用一套接口）；最想讲清的是线程模型 —— 读线程只把 socket 字节搬进环形缓冲，数据靠 50ms 定时器里取。
**关键接口**：`cg_net_connect` / `cg_net_listen` / `cg_net_accept`、`cg_net_read` / `cg_net_write`、`cg_net_udp_open` / `cg_net_recvfrom` / `cg_net_sendto`、`cg_net_available` / `cg_net_connected` / `cg_net_peer` / `cg_net_last_error` / `cg_net_close`。
**容易踩的坑**：接收的 timeout 传 0 表示"不等、立刻返回"，没连接时返回 NULL 是正常情况、不是错误；掉线唯一信号是"已连接"变 0，且要先取干净缓冲再回收句柄；UDP 分支不要碰 TCP 那几个接口，错误串是"粘的"，报一次就够。

### modbus（`examples\modbus`）
**它演示什么**：工控上位机的主循环「拼一帧 → 发出去 → 把回来的字节按协议切成一帧帧 → 解帧 → 落到界面」，走 Modbus/TCP 连从站。
**关键接口**：`cg_modbus_build_read`、`cg_modbus_parse`、`cg_frame_init` / `cg_frame_feed` / `cg_frame_take` / `cg_frame_reset`、`cg_net_connect` / `cg_net_read` / `cg_net_write` / `cg_net_connected` / `cg_net_close`。
**容易踩的坑**：切帧不能假设"读一次 = 一帧"；串口上的 Modbus/RTU 没有长度字段，同一套切帧换一种模式即可；等回应期间不再发下一次，超时报超时；从站的异常响应（功能码 | 0x80 + 异常码）要当正常结果处理；定时器回调必须自己重挂。

### darkterm（`examples\darkterm`）
**它演示什么**：只讲深色这一件事 —— `.cgui` 里写 `"dark": true` 让程序一打开就是深色，配色集中在顶层命名样式表，再用运行时接口切换并立即重画。
**关键接口**：`cg_theme_set_dark` / `cg_theme_is_dark`、`cg_edit_scroll_end`、`cg_widget_set_text`、`cg_app_has_window`。
**容易踩的坑**：深色只换运行时那套兜底配色，**写死了颜色的控件不跟随**；`progress` 的槽、`switch` / `checkbox` 的填充仍是浅色系；`listbox` / `table` / `tree` / `tabs` 是系统经典控件、改不动主题，所以这个示例一个都没用；多行输入框没有终端控件那套托管，追加文本后要自己滚到底。

### hextool（`examples\hextool`）
**它演示什么**：面向工控 / 嵌入式调试的纯计算工具箱 —— 同一段输入可按文本或 HEX 两种看法，产出字节视图、校验、编码与整帧报文预览，不碰任何硬件。
**关键接口**：`cg_hex_encode` / `cg_hex_decode`、`cg_bytes_get_u16` / `cg_bytes_get_u32`、`cg_crc16` / `cg_crc32`、`cg_hash`、`cg_base64_encode` / `cg_base64_decode`、`cg_url_encode` / `cg_url_decode`、`cg_proto_build`。
**容易踩的坑**：解析出的字节有上限，超了明确提示；`cg_proto_build` 的长度字节最大 255，载荷超过时只取前 255 个并注明；编辑框在就绪钩子里预填样例，所以自检能把每条路径都跑到，且全程不弹窗。

### filecheck（`examples\filecheck`）
**它演示什么**：面向固件与镜像发布的纯离线工具 —— A/B 两槽选中后给出大小与多种摘要，比对（先比大小再比 SHA256）、逐字节找差异、复制 / 导出报告，文件可拖进窗口按顺序落槽。
**关键接口**：`cg_file_size`、`cg_hash_file`、`cg_crc32_file`、`cg_file_read_bytes`、`cg_clip_set_text`、`cg_file_write`。
**容易踩的坑**：逐字节比对只在两个文件都读得动且不太大时才做，超限改为比摘要、不硬读进内存；差异全部计数但表格只列前若干条；空文件与打不开必须分清；全程不 malloc/free，只用框架堆串配 `cg_free`。

### traytool（`examples\traytool`）
**它演示什么**：讲一类"没有主窗口也一直在"的程序 —— 启动就建托盘图标，点窗口关闭只是藏进托盘（进程继续跑），真正退出走菜单动作或快捷键；五条命令由一个回调服务，附带剪贴板、整窗截图、深浅主题切换。
**关键接口**：`cg_tray_set` / `cg_tray_balloon` / `cg_tray_remove` / `cg_tray_action`、`cg_cancel_close` / `cg_win_show`、`cg_win_screenshot`、`cg_app_data_dir` / `cg_path_join`、`cg_clip_set_text`、`cg_theme_set_dark` / `cg_theme_is_dark`。
**容易踩的坑**：退出前必须移除托盘图标，少这一句托盘里会留一个死图标；右键点托盘不会自动弹菜单（框架没有"在光标处弹菜单"的接口），这里改把窗口叫回前台；凡需窗口 / 托盘 / 对话框 / 截图处先问有没有窗口，自检才能跑干净。

### shottool（`examples\shottool`）
**它演示什么**：按 QQScreenShot 那类工具自实现的完整截图链路 —— 托盘左键 / 面板按钮 / 全局热键 `Ctrl+Alt+A` 三个入口服务同一条动作；自己先藏起来、隔一拍抓整屏，把截图设成**画板背景图**后拖框选；窗口切无边框贴到选区，标注（矩形 / 椭圆 / 箭头 / 画笔 / 文字）录成绘制命令；**成品 = 抓画板自己**（背景图 + 命令回放恰好是"选区 + 标注"），存 `ScreenShot<日期时间>.png` 并写进剪贴板，还能钉成贴图。
**关键接口**：`cg_hotkey_set`（全局热键，后台也按得到）、`cg_screen_size` / `cg_screen_capture`（屏幕抓取，逻辑像素入参）、`cg_win_set_border` + `cg_scale_px` + `cg_win_set_pos` / `cg_win_set_size`（面板 ↔ 全屏 overlay 切换）、`cg_widget_set_image` 作用在 canvas 上（画板背景图）、`cg_widget_screenshot`、`cg_clip_set_image`、`cg_set_timer`（藏窗口后隔一拍再抓）、`cg_cancel_close` / `cg_tray_*`。
**容易踩的坑**：画板是不透明自绘控件，"盖在图上"必须靠背景图能力而不是透明叠加；`PrintWindow` 发的是 `WM_PRINT`，画板不接这条就抓出空图**而且照样报成功**；藏窗口后立刻抓会把正在消失的自己截进去；面板位置尺寸只许在空闲态记录，否则 overlay 的 move/size 会把面板矩形覆盖掉；改边框只动 `GWL_STYLE` 且必须带 `SWP_FRAMECHANGED`。能力边界（OCR / 录屏 / 截长图 / 多屏 / 半透明遮罩不做）照实写在示例 README 里。

### datarec（`examples\datarec`）

### logfilter（`examples\logfilter`）

### dataview（`examples\dataview`）
**它演示什么**：只教一件事 —— 几万行数据不许一次塞进表格；整份 CSV 只读一遍把每行「偏移 + 长度」记进固定数组（**不复制行内容**），再分页（每页 200 行）+ 按需渲染，排序也只排那张偏移数组。
**关键接口**：`cg_file_size`、`cg_file_read_bytes`、`cg_table_clear` / `cg_table_add_column` / `cg_table_add_row` / `cg_table_begin_update` / `cg_table_end_update`、`cg_file_write` / `cg_file_append`、`cg_status_set` / `cg_status_setf`。
**容易踩的坑**：CSV 只认逗号与换行，不处理引号转义、不处理字段内换行、不转码（别的程序另存的 ANSI/GBK 中文会乱码）；文件超过 16 MB 只解析前一段并在状态栏写明「已截断」；全部固定数组、没有任何 malloc/free，行数 / 列数 / 单元格长度超了会明说；「统计」**并排算「当前页」与「全部行」**，就是让"只看当前页就下结论"这个坑当场显形。另外，翻页是"先清空再逐行填"，必须用 `cg_table_begin_update` / `cg_table_end_update` 包住 —— 不包的话"填 200 行 = 整表重建 200 次"，界面会一直闪（用户实测报回来的）。交互上还有一条：**排序是显式按钮**（选「排序列」→ 点「排序」，方向看「降序」勾选）；**双击表格里任意一格 = 直接改这一格** —— 双击事件本身只带行号，列号用 `cg_table_last_col()` 问，再用 `cg_input_box()` 弹输入框（原值预填且全选），回车即写回。编辑**只改内存、绝不回写原文件**（要留档用「导出全部行」另存），新值含逗号 / 引号 / 换行会被拒绝 —— 示例的 CSV 不做引号转义，写进去会把行结构搞坏。

### envsnap（`examples\envsnap`）

**关键接口**：`cg_file_read` / `cg_file_write` / `cg_open_file_dialog`（清单的读入与存回）、`cg_dialog_open` / `cg_dialog_close` / `cg_widget_set_text` / `cg_widget_text`（添加与修改共用的表单：三个字段一次填完一次提交，校验不过留在框里改）、`cg_input_box`（查询关键字）、`cg_tree_add` / `cg_tree_selected` / `cg_tree_clear` / `cg_tree_count`、`cg_env`、`cg_dir_list` / `cg_dir_exists`、`cg_file_size`、`cg_save_file_dialog`、`cg_clip_set_text`。
**容易踩的坑**：运行时只提供"按名取一个环境变量"、没有"枚举环境变量"的接口，所以这里列一份常用清单；注册表只有"读一个值 / 写一个值"（且仅限当前用户、仅字符串），**没有枚举子键 / 列举值的接口**，所以"注册表浏览器 + 导出 .reg"这条路走不通 —— 这也是本示例换题材的原因，写进了它的文件头。

### htmlreport（`examples\htmlreport`）

### settings（`examples\settings`）
**它演示什么**：同一组设置（上次目录 / 字号 / 深色 / 最近文件）存进**三个后端**并排对比 —— INI 文件、注册表 HKCU、用户数据目录里的文本文件；换后端保存后旧后端的值仍留在原处，用一张对比表把这件事摊开，一眼看出"三个后端各存各的"。
**关键接口**：`cg_ini_read` / `cg_ini_write`、`cg_reg_read` / `cg_reg_write`、`cg_file_read` / `cg_file_write` / `cg_file_delete`、`cg_app_data_dir` / `cg_path_join`、`cg_time_now`。
**容易踩的坑**：注册表接口**只能按名读写字符串值**（子键相对 HKCU），**没有**枚举子键 / 列举值 / 删值 / 删键的接口 —— 所以"清空"只能把每个值写成空串，读取侧也按"空 = 没设"处理；三个后端都没有锁与事务，两个进程同时写同一个后端会互相覆盖；本示例固定写 `HKCU\Software\CStackGUI\examples\settings`、绝不碰用户真实设置，并且开窗时会先做一次**注册表往返自测**（写一个探针值再读回比对），把"这套接口到底通不通"当场报在日志里。

### encconv（`examples\encconv`）
**它演示什么**：处理"别人给的一批 GBK 老文件"—— 枚举目录、判定编码、预览前几行、GBK ↔ UTF-8 互转 + 换行统一（保持 / CRLF / LF）+ 可选写 BOM，最后统计「转换 / 跳过 / 失败」。也支持命令行点名一个目录直接跑一遍（只另存、不覆盖）。转换参数还能写成 **INI 任务单**（`[task]` 节的 `dir` / `direction` / `newline` / `bom` / `overwrite`）：界面点「导入 INI 配置」逐键读进界面（缺项保持当前值、非法值点名报出），或命令行 `encconv.exe task.ini` 直接按单跑 —— 演示"外部 INI 配置文件导入"这种工控常见用法（运行时 `cg_ini_*` 没有枚举节/键的接口，所以任务单是键名固定的表单，不是任意 INI 全量解析）。**开箱可用**：「造示例文件」一键造 4 个示例（3 个真 GBK 中文文件 + 1 个纯 ASCII 对照）+ 1 份示例任务单 `task.ini` 并自动枚举；预览疑似 GBK 的文件时把**同一份字节的两种解读并排贴出来**（A 按 GBK 正确解 = 转换后的样子 / B 按 UTF-8 强行解 = 现在双击文件看到的乱码），"价值"一眼就看得见。
**关键接口**：`cg_dir_list` / `cg_file_exists` / `cg_file_size`、`cg_file_read_bytes` / `cg_file_write_bytes`、`cg_path_join` / `cg_path_ext`、`cg_gbk_to_utf8` / `cg_utf8_to_gbk`、`cg_ini_read` / `cg_ini_write`、`cg_str_format`。
**容易踩的坑**：**判定只是猜**（先按严格 UTF-8 校验，不合法才判"疑似 GBK"；纯 ASCII 谁都合法、GBK 内容偶尔恰好也是合法 UTF-8）—— 界面、日志、表格结论列都照实说，不装作识别得准；文件接口只有整读，单文件超 8 MB **只跳过不截断**（截一半的文件两边都不合法）；没有改名接口，所以"覆盖原文件"要**两步确认**、默认一律另存新文件（另存名是**换掉原扩展名**再加后缀：`参数表.txt` → `参数表.utf8.txt`；早先是直接追加，出来是 `参数表.txt.utf8.txt` 那种双后缀）；**方向下拉的值 0 就是 GBK→UTF-8，而候选判断要的是布尔** —— 把索引当布尔传会把候选判反（真机实测踩过：已经是 UTF-8 的文件被双重编码，真正的 GBK 文件反倒跳过），代码里留了注释；任务单把 `overwrite` 写 1 也只是把勾选填上，**导入不绕过两步确认**，命令行自动跑永远只另存。

### drawpad（`examples\drawpad`）
**它演示什么**：画板 —— 鼠标拖拽作图（直线 / 矩形 / 椭圆 / 文字 / 自由笔）、撤销 / 重做 / 清空、导出 PNG。最想讲清的是：**画板上的图形不是像素，而是被录制的绘制命令**，重绘时按序回放。
**关键接口**：`cg_canvas_clear` / `cg_canvas_set_color` / `cg_canvas_set_line_width` / `cg_canvas_line` / `cg_canvas_rect` / `cg_canvas_ellipse` / `cg_canvas_text`、**画板自己的鼠标三件套**（`mousedown` / `mousemove` / `mouseup`）+ `cg_event_x` / `cg_event_y`（坐标就是画板内逻辑像素）、`cg_widget_screenshot`、`cg_app_data_dir` / `cg_path_join`。
**容易踩的坑**：**鼠标事件必须挂在画板自己身上，不能挂窗口级** —— 按下 / 移动 / 抬起落在画板这个子窗口上时消息只送给画板，父窗口一辈子收不到（早先挂 `app.events` 的写法在真机上"按下拖动毫无反应"）。画板事件里的坐标**就是画板内**逻辑像素，不用再减 `cg_widget_x/y`；也正因为图形只是"被录制的命令"，**没有"擦掉某一笔"的接口** —— 撤销只能"丢掉最后一条 → 清空记录 → 重放剩下的"，所以命令表得自己存一份，它才是可撤销的真相来源；事件名是 `CG_EVENT_*`，写成 `CG_EV_*` 编译期就撞墙（gcc 会替你纠正）。另外画板**没有"预演一笔"的接口**（任何 `cg_canvas_*` 调用都会被录下来），所以"拖动中的橡皮筋预览"只能做成"临时命令 + 整表重放"，松手再正式提交（示例里是 `preview_op`，下一次移动覆盖那个临时槽位）。
**（缺口已补，2026-09-28 后续）**：运行时给 `canvas` 补上了自己的 `mousedown` / `mousemove` / `mouseup`（按下时自动捕获鼠标、坐标就是画板内逻辑像素），本示例随即把三个事件改挂在画板上，并用合成键鼠在真机拖了一笔验证：日志出现作图记录、画面上出现新笔画。早先"画板不能拖拽作图"的结论已作废。

### toolbox（`examples\toolbox`）
**它演示什么**：工具箱启动器，功能面与界面形态对标开源项目 mxx1-toolbox —— 8 个页签（常用/常用设置/我的工具/系统工具/清理优化/隐私设置/应用管理/右键增强）、页内分组条 + 密集按钮墙（命名样式 sect/install/remove）、顶部搜索框即时过滤、状态栏 + 非模态日志对话框双路反馈、内存版「最近使用」（去重、最新在前、最多 8 条）、底栏功能带（「本页 X 个（共 Y 个）」计数 + 搜索/日志/设置/关于/检查更新，其中设置 = 深浅主题切换）。最想讲清三件事：**一个回调服务整面按钮墙**（66+ 按钮绑同一个 `on_tool_click`，回调里用 `cg_widget_id(self)` 反查命令表）；**成对「装上/撤掉」开关**——落点是本工具箱自己的沙箱键 `HKCU\Software\CStackGUI\examples\toolbox`，控制的是本程序自身行为（日志镜像 / 时间戳 / 自动切搜索页 / 记录最近使用 / 沙箱标记），真改真还原，配「查看曾改动 / 还原全部」；**右键菜单管理**——「扫描右键菜单」用 `cg_reg_subkeys` 枚举 HKCU 用户区五个区域（`*\shell` / `Directory\shell` / `Directory\Background\shell` / `Drive\shell` / `AllFilesystemObjects\shell`）的子键，逐项读 `MUIVerb` / `command` 默认值 / `LegacyDisable`，表格列出「区域 / 标题 / 命令 / 状态（在用·已隐藏·无命令）」+ 统计；工具箱自己的两条菜单（复制文件路径 / 在此处打开终端）用 `reg.exe add/delete` 走 `cg_run_process(cmd, 1)` 真装真撤——注册表接口没有删值能力，用系统 reg.exe 才删得干净。
**关键接口**：`cg_reg_subkeys`（枚举子键，'\n' 分隔，风格同 `cg_serial_list`）、`cg_reg_read` / `cg_reg_write`（沙箱开关）、`cg_run_process`（wait=0 启动工具、wait=1 等 reg.exe 拿退出码）、`cg_dialog_open_nonmodal`（日志窗）、`cg_theme_set_dark` / `cg_theme_is_dark`、`cg_message_box`、`cg_ini_read` / `cg_file_write_bytes`（我的工具槽位）、`cg_table_add_row` / `cg_table_clear`（扫描结果）、`cg_widget_id`、`cg_widget_value`、`cg_widget_list_addf` / `cg_widget_list_clear` / `cg_widget_list_item`、`cg_tabs_select`、`cg_widget_focus`、`cg_app_has_window`。
**容易踩的坑**：**凡真启动外部程序 / 写注册表 / 弹对话框的回调先问 `cg_app_has_window()`** —— 自检会合成触发每个按钮的 click，不挡住就会在 CI 上真的拉起一堆程序；启动失败（返回 -1）必须反馈到状态栏，不许静默；「.cgui 加了按钮、C 表忘登记」这类不同步，回调里会写一条「不同步」日志，自检输出里 grep 就能抓到；**成对开关的方向解析别用硬编码偏移猜** —— `id+4` 是 `"_on"` 不是 `"on"`（2026-10-11 真机探针抓过：方向永远解析成"撤掉"，reg 里全是空值，界面却看不出异样），解析前先核对自己 id 的字面形态；**`cg_run_process` 不经过 cmd 解释**，`&` 连接、重定向、`%VAR%` 展开统统无效 —— 要多条命令就多次调用，要环境变量展开就套 `cmd /c`；注册表接口只能读写字符串值、没有删值与枚举子键以外（现在有 `cg_reg_subkeys`）的能力，所以「还原」= 写空串（值空 = 未设），要删干净就借系统的 `reg.exe`；我的工具用 INI 固定槽位（`[t1]..[t8]` 的 name/cmd），因为 `cg_ini_*` 没有枚举节/键的接口。
